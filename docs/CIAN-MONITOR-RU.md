# Новые объявления: сохранённый поиск ЦИАН

Откройте «Новые объявления», вставьте ссылку результатов поиска ЦИАН и сохраните настройки. Для первой настройки можно использовать обычный поиск аренды квартир Москвы с нужной ценой, комнатами и метро. Система сортирует выдачу по дате и начинает с первой страницы. Отдельное объявление в это поле не подходит.

Первое успешное чтение создаёт **базовый снимок**: найденные старые ссылки не объявляются новыми. Явный успешный JSON-ответ с пустым `data.offersSerialized` и нулевым `offerCount`/`offersCount` тоже создаёт пустой базовый снимок: первое позднее объявление тогда действительно попадает в «Новое». Пустой HTML, неизвестная схема и ответ с ошибкой/проверкой такого снимка не создают. При следующих проверках новые ID попадают в категорию «Новое». Полная карточка, мебель, перевод и фотографии автоматически не сканируются: нажмите «Сканировать», чтобы запустить привычный импорт выбранного объявления. Мониторинг не переписывает существующие карточки.

## Расписание и хранение

Включённый монитор работает на Mac вместе с сервером. По умолчанию интервал — 60 минут; доступны интервалы от часа до суток. Состояние, ID, прочтение и следующая проверка сохраняются в отдельной `listing-watch.sqlite3`, поэтому перезапуск сервера не превращает всю выдачу в новую. Когда Mac выключен или спит, проверки не идут; после возобновления выполняется одна просроченная проверка без пачки пропущенных запросов.

Один проход ограничен двумя страницами, не более 100 распознанными ссылками, без посещения самих квартир и без загрузки фотографий. Это обзор начала выдачи, а не гарантия полного охвата всего рынка: при большом количестве публикаций между проверками часть новых объектов может оказаться дальше второй страницы. Интервал не сокращается незаметно. В базе разрешено до 50 000 записей; при достижении лимита проверка сообщает об этом вместо удаления старых ID и повторных ложных уведомлений.

Готовый процесс чтения имеет общий предел 35 секунд, включая запуск браузера, DNS и JavaScript. Он выполняется в собственной группе процессов; остановка сервера сначала даёт ему завершить обычное закрытие, затем при зависании завершает только созданную им группу. Контроллер ждёт завершения до 40 секунд, а не оставляет окно Chrome с заблокированным профилем. Ручной импорт использует прежнюю общую блокировку браузера.

При ошибке увеличивается интервал повторной попытки, максимум до суток. Ошибки, последний успешный проход, ближайший запуск, размер последнего результата и неполнота охвата отображаются отдельно. «Проверить сейчас» выполняет один проход, даже если периодическое расписание выключено; несколько нажатий не создают параллельных браузеров.

## Дата размещения и первое обнаружение

`publishedAt` заполняется только явной датой источника: например, `creationDate`, `datePublished` или `addedTimestamp`. В JSON сохраняется имя исходного поля. Строгая дата ISO с часовым поясом и Unix timestamp преобразуются в абсолютное время; дата без времени сохраняется как дата. Относительные и неопределённые подписи остаются подписью источника, без выдуманного времени публикации.

`firstSeen` — время первого обнаружения нашим монитором. Оно **не подставляется вместо даты публикации**. `updatedAt` и другие даты обновления не считаются датой размещения. Объявление с известной датой до базового снимка, поднявшееся выше в выдаче позднее, остаётся в общем списке и не обозначается новой публикацией. Если дата отсутствует, «Новое» означает новую обнаруженную ссылку, и в интерфейсе отдельно показано время обнаружения.

## Три способа чтения

- **HTML** — обычный HTTPS GET поисковой страницы. Читаются известные карточки и JSON, который сама страница уже содержит. JavaScript строками не исполняется. Видимые проверки браузера дают состояние «нужно внимание», а не пустой успешный снимок.
- **API** — экспериментальный внутренний endpoint поиска, описанный в открытых проектах GitHub. Это не обещание официального API всего рынка. Страница и сортировка у наблюдаемого ответа проверяются; соответствие всех внутренних фильтров неизвестной схемы не заявляется, поэтому найденные ссылки остаются кандидатами для ручного полного импорта. Преобразуются только явно поддерживаемые фильтры квартиры, региона, комнат, цены и срока; для неподдерживаемого фильтра настройка отклоняется с предложением выбрать HTML/Chrome, вместо расширения поиска без ведома пользователя. API ключ кабинета сюда не передаётся.
- **Chrome** — обычное отдельное окно профиля redcn, совместное с ручным импортом. Оно посещает только две поисковые страницы, закрывается по окончании и не запускается одновременно с ручным импортом. Готовый JSON-ответ поиска, который страница сама запросила, также читается: дополнительных API-запросов или заголовков для этого не создаётся; ответы кабинета и предыдущей страницы игнорируются. Переходы Chrome проверяются до отправки: только публичный HTTPS-адрес исходного поиска ЦИАН с теми же фильтрами; внешние, локальные и изменяющие фильтр перенаправления блокируются. Навигация сторонних iframe также ограничена, service worker для этого собственного контекста отключён, чтобы не скрывать запросы от проверки. Проверка ЦИАН не обходится автоматически. При её появлении показано состояние внимания; можно пройти её при обычной ручной загрузке в профиле redcn и повторить поиск.

Из произвольного DOM-текста карточки не угадываются цена и площадь. При наличии структурированного API-ответа числовая цена помечается рублями только при явном `priceRur` либо рублёвой валюте источника. Никакие телефоны, cookies, токены или ключи не требуются в настройках мониторинга и не сохраняются в его результатах.

Официальный API ЦИАН, который описан на [странице сервиса](https://promo.cian.site/api), предназначен для профессионального кабинета/CRM. Найденные GitHub проекты используют другой, внутренний поисковый endpoint; его доступность может изменяться. Ссылки, лицензии и границы исследования: [CIAN-MONITOR-RESEARCH.md](CIAN-MONITOR-RESEARCH.md).

## HTTP для интерфейсов Mac и телефона

Обработчик вызывается только после существующей авторизации и CSRF-проверки:

| Маршрут | Назначение |
|---|---|
| `GET listing-watch` | Настройки, расписание, базовый снимок, счётчики и ошибка |
| `POST listing-watch` | `{enabled, searchUrl, intervalMinutes, adapter}` |
| `GET listing-watch/items?category=new&limit=50&before=…` | Новые либо все ссылки текущего поиска, страницы по курсору |
| `POST listing-watch/check` | Один асинхронный проход |
| `POST listing-watch/read` | `{ids:["cian:123"]}` — отметить прочитанными |

Существующие рабочие БД, личные досье и очередь полного импорта этим модулем не изменяются. При смене поискового запроса создаётся свой базовый снимок; история прежнего поиска сохраняется отдельно. Сбор диагностического `tg.zip` после десяти ручных проверок квартиры — отдельный сценарий: часовые проходы выдачи в эти десять проверок не включаются.
