# Облачная копия, перенос на другой Mac и уведомления

## Приватная R2-копия

Реализация: `cli/cloud_backup.py`, `worker/cloud-backup.mjs`,
`web/cloud-backup.mjs`. Сервер Mac экспортирует тот же проверяемый workspace ZIP,
затем AES-256-GCM шифрует его отдельным ключом восстановления. Ключ шифрования
никогда не передаётся Worker. Owner capability и cipher key различаются.
AAD связывает ciphertext с владельцем и ID копии; перенос зашифрованных байтов
под чужое имя не проходит проверку.

Sites подключает logical R2 binding `BUCKET`; gateway остаётся owner-private.
Дополнительная capability проверяется на каждом list/put/get. Первичная
регистрация требует `REDCN_BACKUP_REGISTRATION_KEY` из Sites runtime env.
Реквизиты gateway отправляются только этому Site заголовком
`OAI-Sites-Authorization`, не как query-параметры. В редиректы они не следуют.

Worker хранит **только ciphertext**, передаёт request/response stream напрямую
R2 и проверяет SHA-256 через R2 put option. Нет двойного буфера на 128-МБ
Worker. Запись ID условная: другой файл прежнюю копию не перезаписывает.
Повтор тех же bytes/id допускается. Операции удаления нет.

Cloud limit — **64 MiB** encrypted bundle; общий локальный ZIP/CLI сохраняет
свой отдельный предел 512 MiB. Лимиты показаны в интерфейсе. Конфигурация Mac —
только backend `cloud-backup-credentials.json`, mode 0600; она исключена из
portable ZIP. Публичный status не отдаёт ключи. В браузере реквизиты вводятся
только в password inputs и очищаются после запроса, не пишутся в storage.
Отдельный recovery-файл скачивается владельцем явной кнопкой и не содержит
Sites service bearer. Храните его вне исходного Mac.

Отправка **по умолчанию выключена**. Оператор сначала подключает приватный
Site, сохраняет recovery-файл, подтверждает это и разрешает копирование.
Даже после включения отправка начинается по кнопке. Здесь нет незаявленного
фонового копирования или выгрузки реальной базы при установке обновления.
Телефонам, включая paired owner, whole-workspace cloud routes запрещены.
Восстановление допускается только в новую папку, с теми же валидаторами
библиотеки/словаря/фото/досье. Подключения телефонов не переносятся, исторические
клиентские материалы требуют пересоздания.

### Реальная облачная приёмка

Облачная приёмка выполняется после отдельного явного подключения владельцем
и приватной публикации R2-enabled source. Установка v26 на Mac и push в GitHub
её не запускают и облачное копирование не включают. Только публичная synthetic fixture из
`tests/fixtures/macos-portability` используется для roundtrip; реальная база,
договоры, фотографии и auth-файлы пользователя не читаются и не загружаются.
Проверка выполняется с временным 0600 конфигом и временной новой папкой:
регистрация test owner → encrypt/upload → list → download/checksum/decrypt →
`workspace_backup.restore_workspace` → `portability_proof.semantic_state`.
После неё сохраняется очищенный receipt без ключей. Только локальный mock R2
или unit-тест не объявляется фактическим облачным восстановлением RCN-058.

Первичные API docs:
https://developers.cloudflare.com/r2/api/workers/workers-api-reference/
https://developers.cloudflare.com/r2/api/workers/workers-api-usage/

## Отдельный Mac

`scripts/portable-mac-proof.py` всегда создаёт собственный temporary workspace.
Mac1 export уже оформляется как public synthetic fixture; `mac-portability`
job восстанавливает его на новом GitHub-hosted macos-15. Он сравнивает карточки,
связи, attachment bytes, original/crop bytes, template, версии HTML, approved
словарь и учебные счётчики. Другой ID карточек ожидаем, потеря данных — ошибка.
Результат этого hosted Mac job, а не Linux mock, нужен для RCN-241.

## Собственный браузер как канал доставки

`web/device-notifications.mjs` добавляет в мониторинг явный выбор «этот браузер»
и название устройства. Системное разрешение запрашивается **только** внутри
нажатия оператора. На iPhone требуются HTTPS, установленное приложение и
поддержка системных уведомлений. Это не приёмка физического iPhone.

Доставка работает, пока приложение открыто. Это не закрытое Web Push и не
Telegram/почта. Серверные события создаются после явного включения внутренних
уведомлений сохранённого поиска. Идентификатор workspace подтверждается
аутентифицированным GET, backend не принимает посторонний адрес получателя.

Журнал IndexedDB привязан к workspace. Atomic read/write transaction выдаёт
одну lease на notice; одинаковый native `tag` заменяет сообщение при повторной
попытке. Успех запоминается между вкладками/запусками. Ошибки повторяются с
задержками, максимум пять попыток; выключение и logout прекращают новые
попытки, поздний результат уничтоженного UI не вызывает новую доставку.
Доставка, уже переданная ОС, не является гарантией прочтения оператором.
Ключей внешних сервисов нет; тексты заметок/договоров и raw HTML в ledger не
сохраняются. В продакшене opt-in остаётся выключенным до выбора оператора.

Unit-тесты проверяют opt-in/dedup/retry/disable/два owner scopes. Отдельный
Chrome fixture воспроизводит нажатие выбора устройства и разрешения с mock
OS Notification, но **реальной IndexedDB**; параллельные store connections
получают одну lease. Ни одному реальному человеку уведомление этими тестами
не отправляется.
