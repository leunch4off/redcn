# Подключение, загрузка и альтернативы Cloudflare

Проверено 30 октября 2026. Mac остаётся сервером: объявления, Chrome, оригиналы фотографий и PDF обрабатываются на нём. Телефон получает готовые карточки. Адрес `192.168.1.64` доступен в домашней сети; для улицы нужен защищённый внешний маршрут.

## Что произошло при проверке

Mac был перезагружен, редактор 8765 и телефон 8767 не работали. После запуска обе страницы вернули HTTP 200. Предыдущая временная ссылка Cloudflare закончилась вместе с процессом. Новый Cloudflare-коннектор не подключился за 35 секунд. Это подтверждает проблему текущего маршрута, но не устанавливает её причину и не означает одинаковую блокировку у всех операторов.

## Подробная загрузка

На телефоне блок «Подробности подключения» показывает фактические этапы: получение страницы, ответ Mac, проверка сессии и получение карточек. Видны адрес, прошедшее время и этап ошибки. При успехе блок сворачивается. При ошибке есть повтор и конкретная подсказка; HTML-ошибки шлюза 502/503/504 отличаются от недоступного Mac.

Начальная API-проверка имеет общий бюджет 9 секунд. Если провайдер блокирует сам HTML или DNS до открытия страницы, интерфейс ещё не загружен и показать свои этапы не сможет. Это проверяется с Mac: **Телефон → Проверить соединение**. Отдельно отображаются локальный редактор, телефонный сервер, состояние туннеля, DNS и внешний HTTPS. Проверка с Mac не заменяет тест с телефона через мобильного оператора.

## Варианты внешнего подключения

| Вариант | Что требуется | Адрес и ограничения | Применение |
| --- | --- | --- | --- |
| [Tuna](https://tuna.am/docs/tunnels/http.md) | Аккаунт, CLI на Mac | Документация предлагает постоянный бесплатный поддомен, регион `ru`, без ограничения времени; на бесплатном режиме возможна стартовая плашка | Первый вариант для проверки из РФ |
| [ngrok](https://ngrok.com/docs/pricing-limits/free-plan-limits/) | Аккаунт, CLI и авторизация | Бесплатный dev-домен сохраняется после перезапуска; квоты и стартовая плашка сервиса | Резервный вариант; проверить своего оператора |
| [Pinggy](https://pinggy.io/docs/) | SSH; быстрый режим без аккаунта | Бесплатная сессия 60 минут, адрес меняется | Разовая проверка; постоянная иконка неудобна |
| VPS в РФ + домен + Caddy + обратный SSH | Аренда VPS, домен, SSH-ключ | Постоянный HTTPS-адрес под вашим управлением | Основной вариант для регулярной работы |
| [Tailscale](https://tailscale.com/kb/1151/what-is-tailscale) | Аккаунт и клиент на Mac/iPhone | Частная сеть; для установленного HTTPS-приложения нужна отдельная настройка имени/сертификата | Закрытый доступ к своим устройствам |

Доступность сайта провайдера не доказывает доступность туннеля. На этом Mac сайты Tuna, ngrok и Pinggy открылись с проверкой сертификатов; SSH-соединение к Pinggy и localhost.run не установилось в шестисекундной пробе. Доступность через конкретного мобильного оператора ещё не подтверждена. Условия провайдеров проверяйте перед оформлением тарифа.

## Tuna: подключение к этому приложению

1. Установите CLI по [официальной инструкции](https://tuna.am/docs/guides/install/install-cli.md): `brew install yuccastream/tap/tuna`. Создайте аккаунт в Tuna, выполните `tuna login --web` и завершите вход самостоятельно. Токен не вставляйте в карточки, репозиторий или переписку.
2. Оставьте сервер МОСТ запущенным. В отдельном терминале выполните:

   ```bash
   tuna http 127.0.0.1:8767 --location=ru --https-redirect --inspect=false
   ```

   `--inspect=false` отключает просмотр трафика в инспекторе Tuna. Для закреплённого в аккаунте поддомена добавьте `--subdomain=ВАШ_ПОДДОМЕН` по документации сервиса. Не включайте переписывание Host: приложение проверяет точное внешнее имя.
3. На Mac в **Телефон → Другой HTTPS-адрес** вставьте выданный корневой адрес вида `https://ваш-домен` и сохраните. Завершающий `/phone/` не нужен. Приложение переключится с Cloudflare на внешний туннель, которым управляет Tuna.
4. Нажмите **Проверить соединение**, откройте ссылку `/phone/` в Safari через мобильные данные, пройдите стартовую плашку провайдера, если она появилась, и введите 8 цифр с Mac.
5. Установите именно этот HTTPS-адрес на экран «Домой». Для устойчивой иконки закрепите постоянный поддомен. При смене origin требуется новая установка и вход.

Аккаунт Tuna и туннель не созданы автоматически: для этого нужен ваш вход. Настройка внешнего адреса в МОСТ не запускает сторонний CLI. Его нужно держать запущенным либо отдельно настроить автозапуск.

Для ngrok порядок такой же: после установки/входа запустите `ngrok http 8767`, затем сохраните выданный HTTPS-origin в МОСТ. Инспектор и хранение трафика на стороне провайдера настройте в его аккаунте. Для Pinggy официальный быстрый пример адаптируется как `ssh -p 443 -R0:localhost:8767 free.pinggy.io`; первая проверка ключа SSH производится по инструкции провайдера. Проверку SSH-ключа не отключайте.

## Постоянный адрес через VPS в РФ

Это схема установки для вашего VPS, а не уже выполненное развёртывание. Нужны приобретённый сервер, публичный IPv4, домен и ваш SSH-доступ. Например, [Timeweb Cloud](https://timeweb.cloud/services/vds-vps) указывает российские регионы; выбрать можно и другого провайдера.

На VPS домен направляется A-записью на его IPv4. Установленный [Caddy](https://caddyserver.com/docs/quick-starts/https) получает TLS-сертификат и передаёт запросы только в обратный туннель. Пример Caddyfile, где имя заменяется вашим:

```caddyfile
phone.example.ru {
    @phone path /phone/* /api/phone/*
    handle @phone {
        reverse_proxy 127.0.0.1:18767
    }
    handle {
        respond 404
    }
}
```

На Mac исходящий SSH-туннель, после настройки отдельного ограниченного пользователя/ключа на VPS:

```bash
ssh -N -T -o ExitOnForwardFailure=yes \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
  -R 127.0.0.1:18767:127.0.0.1:8767 user@YOUR_VPS
```

Порт 18767 остаётся loopback на VPS. Не открывайте его наружу и не направляйте туннель на порт редактора 8765. Caddy сохраняет внешний Host; не подменяйте Origin. В МОСТ сохраните `https://phone.example.ru` как другой HTTPS-адрес, выполните диагностику и тест с мобильного интернета. SSH-автовосстановление и запуск Caddy нужно настроить на конкретном VPS. Пока доступа к такому серверу нет, RCN-247 остаётся в плане.

## Автозапуск сервера на Mac

Из папки проекта:

```bash
.venv/bin/python scripts/macos-service.py install
.venv/bin/python scripts/macos-service.py status
```

Сервер запускается после входа пользователя в macOS и перезапускается при сбое. Окно терминала держать открытым не нужно. Редактор остаётся на `http://127.0.0.1:8765/`, телефон — на 8767. Если уже работает эта же копия МОСТ, второй экземпляр не создаётся. Mac должен быть включён и доступен; автозапуск не отменяет сон или выход пользователя из macOS.

Удалить автозапуск с сохранением карточек и документов:

```bash
.venv/bin/python scripts/macos-service.py remove
```

Журнал: `~/Library/Logs/redcn/server.log`. Коды входа и содержимое карточек в него не выводятся. Настройка не меняет DNS, VPN, роутер или системный сон.
