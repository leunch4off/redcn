# Импорт на Mac: этапы, время и готовые фотографии

## Почему после Chrome возникала ошибка Node.js

На Mac уже установлен Node.js 24.4.0 в `/usr/local/bin/node`. Запущенный через LaunchAgent сервер получал короткий PATH и не находил его. Поэтому Chrome успевал прочитать объявление и закрыться, а генерация китайского текста после него останавливалась.

Теперь генератор и анализатор HTML находят поддерживаемый Node.js по абсолютному пути, включая каталоги Homebrew. Версия проверяется до открытия Chrome. Сам генератор остаётся общим для сайта и CLI; ошибки отсутствия runtime, неподдерживаемой версии и выполнения различаются. В пользовательский LaunchAgent добавлены обычные каталоги Node.js. Ничего устанавливать повторно на этом Mac не требуется.

Дополнительно проверена совместимость Python с библиотекой фото. В существующей среде Pillow собран для x86_64, а launchd выбирал ARM64 и не мог загрузить расширение. Установщик сервиса теперь проверяет реальные импорты Pillow, Playwright и certifi и явно выбирает совместимую архитектуру. На этом Mac используется уже установленная рабочая x86_64-среда; переустановка библиотек не потребовалась. При переустановке сервиса предусмотрено ожидание завершения прежнего LaunchAgent, чтобы избежать гонки bootstrap.

## Что видно на телефоне

На экране добавления квартиры отображаются текущая операция, прошедшее время, время этапа, реальные счётчики фотографий и список пройденных этапов:

| Этап | Что делает Mac |
| --- | --- |
| Проверка генератора | Проверяет Node.js до долгой загрузки |
| Запуск Chrome | Запускает отдельный профиль и своё окно браузера |
| Загрузка страницы | Ждёт доступное описание, цену и площадь; сообщает, чего пока не хватает |
| Проверка в браузере | Ожидает ручную проверку площадки, если она требуется |
| Прокрутка и догрузка | Прокручивает страницу и собирает доступные отложенные изображения |
| Чтение объявления | Извлекает факты; для свежего кеша объясняет, что Chrome повторно не нужен |
| Китайский текст | Создаёт заголовки, описание и теги общим генератором |
| Фотографии | Скачивает до трёх изображений одновременно, показывает количество |
| Автоматическое кадрирование | Проверяет края каждого фото и повторно проверяет безопасную копию |
| Сохранение | Обновляет карточку на Mac и делает её доступной на телефоне |

Процент ожидания сайта не придумывается. Счётчик прокруток показывает фактические шаги, а не процент готовности объявления. Ручная проверка площадки остаётся ручной; браузерная защита не обходится. При возврате в приложение текущая операция восстанавливается с Mac, включая её результат или ошибку.

Среднее рассчитывается по последним 30 успешным операциям соответствующего вида. Импорт из кеша, загрузка Chrome/HTTP и отдельная подготовка фото измеряются отдельно. Пока измерений нет, показывается прямое сообщение об этом; после выполнения появляются среднее, количество измерений и диапазон. Если задача длится дольше среднего, интерфейс так и пишет. Время ручного подтверждения не выдаётся за предсказуемый обратный отсчёт. В файле измерений нет текста объявлений, ссылок или кодов подключения.

Если текст готов, но часть фото не загрузилась или обработка прервалась по технической причине, карточка сохраняется с явным сообщением о частичной подготовке. Такой быстрый неуспешный проход не искажает среднее. Кнопка повтора продолжает подготовку фотографий существующей карточки и не создаёт повторный импорт текста.

## Фото готовятся автоматически

Новый импорт и подготовка фотографий запускают проверку краёв на Mac. При уверенном распознавании метки возле границы создаётся отдельная обрезанная копия. Результат проверяется повторно. Исходные файлы остаются доступными; сомнительная или слишком глубокая обрезка не применяется автоматически. Фиксированный процент для всех фотографий не используется.

Чтобы не ждать повторную проверку каждого изображения, решения сохраняются по хешу оригинала и версии правил. Сбой OCR не записывается как отсутствие метки. Явно заданная оператором ручная копия имеет приоритет. Ограничения — до 12 секунд на одну автоматическую проверку и до 90 секунд на проход кадрирования; фотографии, не прошедшие безопасную проверку или лимит, остаются целиком. Интерфейс показывает такие результаты и допускает повтор подготовки.

На телефоне по умолчанию открываются **«Готовые фото»**: проверенная копия там, где она создана, и остальные оригиналы. Необрезанные изображения не исчезают из набора. Переключатель **«Оригиналы»** возвращает исходные кадры. Скачивание, системное меню «Поделиться» и ZIP используют выбранный набор. Подготовленный ZIP также содержит все доступные изображения, заменяя только подтверждённые копии.

Это автоматизация скачивания, OCR и правил кадрирования. Безошибочное определение всех водяных знаков и обучение новой нейросети не заявляются. Если метка расположена в центре комнаты или уверенность недостаточна, сохраняется полный кадр.

## Проверки

```bash
PYTHONPATH=cli:tests .venv/bin/python -m unittest test_node_runtime test_job_progress test_auto_photo_crop -v
PYTHONPATH=cli:tests .venv/bin/python -m unittest test_phone_job_browser test_phone_browser -v
```

Браузерная проверка требует установленного Google Chrome и Playwright. Приёмка и фактические измерения фиксируются в [VERIFICATION.md](VERIFICATION.md).
