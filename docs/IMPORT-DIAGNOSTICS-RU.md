# Диагностика десяти ручных импортов ЦИАН

Это временный режим сбора измерений на Mac. Он не запускает десять посещений сам: проверки расходуются только после ручного запуска импорта существующим пользователем сайта. Почасовой мониторинг списка, просмотр карточки и подготовка её фотографий в эту квоту не входят.

Кампания запускается явно на **ровно 10 попыток**. После десятой завершённой попытки сбор отключается и автоматически создаётся `import-diagnostics/tg.zip` в кеше приложения. Обычный импорт продолжает работать. Сбой, отмена и прерывание при перезапуске считаются попытками: иначе зависшие страницы могли бы бесконечно держать диагностический режим включённым. Ручной импорт из кеша также считается и отмечается профилем `import:cache`; для измерения настоящей загрузки источника следует включать обновление исходной страницы.

Архив остаётся на Mac и отдаётся только через защищённый API приложения. Самостоятельной отправки в Telegram, внешнюю модель или другое приложение нет. Имя `tg.zip` — имя диагностического комплекта.

## Что находится внутри

- `manifest.json`: версия, даты UTC, ровно десять результатов, длительности и итог отключения сбора.
- `checks.jsonl`: одна строка на попытку, её каноническая публичная ссылка ЦИАН, исход, времена этапов и блоков страницы, ограниченные данные ошибки.
- `events.ndjson`: до 200 событий на попытку. Есть измеренные время от старта, этап, раздел страницы, счётчики загрузки и признаки ожидания ручной проверки источника.
- `environment.json`: версии Python, общего Node.js, Playwright, Pillow и certifi, тип ОС и архитектура. Проверка Node использует тот же поиск runtime, что импорт, не устанавливает программы и не сохраняет полный путь к исполняемому файлу.
- `summary.txt`: сводка и список наиболее долгих попыток с разбивкой по этапам и разделам.

Этапы: проверка генератора, запуск Chrome, навигация, ожидание ручного подтверждения источника, прокрутка, извлечение, генерация китайского текста, загрузка фотографий, подрезка, сохранение. Разделы: фотографии, описание, характеристики/мебель. При наличии `listing.capture` берутся измеренные `seconds`, `activeSeconds`, число чтений и посещённых блоков, готовность каждого раздела. Если финальное извлечение не состоялось, доступны интервалы между фактически пришедшими событиями. Отсутствующие времена не заменяются предположениями.

Среднее в архиве относится к этим десяти попыткам, включая ожидание пользователя, ошибки и кеш. Оно не подменяет накопленную оценку времени успешного импорта в мобильном интерфейсе. После аварийного завершения оставшиеся незавершённые попытки получают результат `interrupted`; их длительность определяется настенными часами с ограничением в сутки и может включать простой сервера.

## Границы сохранения данных

В комплект не входят cookie, заголовки авторизации, токены, профиль пользователя, договоры, личные заметки, сырые HTML, фотографии и текст объявления. События принимают только заранее разрешённые поля. Сообщения и ошибки ограничиваются по длине; известные учётные данные, адреса электронной почты, телефоны, сетевые URL и локальные пути удаляются. Ссылка самой проверки отдельно канонизируется: только HTTPS-домен ЦИАН и адрес предложения, без query, fragment, логина, пароля и нестандартного порта.

Каталоги имеют режим 0700, база и ZIP — 0600. Имена внутри архива фиксированы. Архив записывается атомарно, проверяется по SHA-256 при скачивании. Символические ссылки вместо каталогов, базы или архива не принимаются. Старый готовый комплект сохраняется под ID кампании в `archives`; `tg.zip` содержит последний завершённый комплект. Прогресс хранится в отдельной SQLite, без изменения рабочих карточек или досье. Допускается до двадцати явно запущенных кампаний; автоматического удаления старых комплектов нет.

## Контракт интеграции

`cli/import_diagnostics.py` не содержит HTTP-обработчика и не заменяет проверку авторизации/CSRF владельцем API.

```python
manager = ImportDiagnostics(cache_directory)
manager.recover_interrupted()  # один раз до приёма заданий после старта сервера

# Только по явной команде пользователя, не при каждом старте сервера:
manager.arm(target=10)

token = manager.begin(job_id, canonical_source_url, manual=True)

def report(message, **fields):
    tracker.update(message, **fields)
    manager.record(token, message, **fields)

try:
    listing = import_listing(..., report=report)
finally:
    manager.complete(token, outcome, progress=tracker.snapshot(),
                     capture=listing.get('capture') if listing else None,
                     error=actual_error)
```

Владелец задания должен завершить диагностическую попытку в `finally`, в том числе при ошибке до открытия браузера. Для фонового мониторинга `manual=False` всегда возвращает `None`, не расходуя квоту. Повторный `begin` для того же job в текущей кампании и повторный `complete` не увеличивают счётчик. Одновременно резервируется не больше десяти попыток. На ошибки самой записи телеметрии обработчик должен реагировать отдельно, не превращая удачный импорт в неудачный; создание ZIP уже обрабатывает ошибки записи без срыва импорта.

`record` понимает существующие `stage`, `section`, `completed`, `total`, `awaitingUser`, `maxTotalSeconds`, `sectionReady`; также допускает измеренные `readyState`, `domReady`, `imagesReady`, `descriptionReady`, `characteristicsReady`, `phase`, `browserChannel`, `pageHeight`, `scrollTop`, `documentBytes`, `textChars`, `imageCount`, `domReads`. Неизвестные поля отбрасываются.

`status()` возвращает `state`, `enabled`, `target`, `reserved`, `completed`, `inFlight`, `remaining`, `campaignId`, `bundleReady`, `bundleError` и краткий список проверок. `remaining` означает число ещё не зарезервированных попыток; при десяти незавершённых заданиях оно равно нулю, а `inFlight` показывает ожидание завершения. Состояния: `idle`, `armed`, `paused`, `finishing`, `complete`.

`pause()` прекращает новые записи в квоту; уже начатые задания могут завершить свои измерения. `arm(10)` возобновляет текущую незавершённую кампанию без сброса счётчика. После полностью завершённой кампании `arm(10)` создаёт новую. `close()` запрещает новые резервации только для экземпляра контроллера. `bundle_asset()` возвращает `(bytes, 'application/zip', 'tg.zip')` последнего завершённого комплекта и может повторить его сборку после устранимой ошибки записи.

Локальные unit-тесты используют временные каталоги и искусственные часы; они не посещают ЦИАН и не расходуют десять живых проверок пользователя.
