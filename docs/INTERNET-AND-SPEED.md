# Работа через интернет и быстрое открытие

## Открыть с улицы

На Mac откройте локальный редактор и раздел **«Телефон» → «Работа с улицы» → «Включить доступ из интернета»**. Когда появится сообщение о работающем внешнем адресе, скопируйте HTTPS-ссылку или выберите её в списке адресов для QR. Откройте ссылку на iPhone через Wi-Fi или мобильный интернет и введите текущие 8 цифр с Mac.

HTTPS-ссылка ведёт только к телефонному интерфейсу. Локальный рабочий стол, его токен и управление подключением остаются на Mac. Карточки, фото и личные документы требуют авторизации; внешние cookie имеют Secure. Исходящий Cloudflare Tunnel не требует настройки маршрутизатора или открытия входящего порта.

Адрес 192.168.x.x остаётся домашним адресом и работает в той же локальной сети. Он не превращается в публичный IP после включения туннеля. Настройки DNS, роутера, VPN и firewall приложение не меняет.

## Установить внешнюю версию на iPhone

Если старая иконка установлена с домашнего адреса, она продолжает открывать домашний адрес. Сначала откройте **новую HTTPS-ссылку в Safari**, войдите по коду и добавьте именно её на экран «Домой». Отдельное приложение при необходимости повторно принимает код с Mac. Mac должен оставаться включённым, с интернетом и запущенным сервером.

Текущий вариант использует **временный Quick Tunnel**. Его адрес действует, пока работает процесс туннеля; после остановки/перезапуска он меняется. Новый адрес показывается на Mac. Для устойчивой установленной иконки после перезапусков нужен постоянный домен/управляемый туннель — RCN-247. Новая DNS-запись может появиться не сразу после запуска; в этот момент не стоит многократно создавать новые туннели.

Кнопка **«Отключить внешний адрес»** закрывает только внешний туннель, сохраняя локальный доступ. **«Отключить доступ»** выключает телефонный сервер и отзывает все сессии. Выбор внешнего режима сохраняется на Mac: следующий запуск телефонного сервера снова создаёт туннель с новым адресом. Обычное закрытие сервера завершает его собственный процесс cloudflared.

## Установка помощника на Mac

Нужен `cloudflared` в `~/.local/bin`, Homebrew или PATH. Приложение само не скачивает и не обновляет исполняемый файл. На текущем Mac помощник установлен из официального ARM64-релиза 2026.10.6; архив проверен по SHA-256, опубликованному GitHub API для release asset. Работает отдельная пустая конфигурация, HTTP/2 и отключённое автообновление; личные настройки Cloudflare не используются.

## Что ускорено

- Редактор, знания и географические индексы создаются по мере обращения. Пустой экран не запускает дизайнер и генерацию публикации.
- Текстовые страницы и JSON используют gzip с ограниченным кешем в памяти. Правило no-store для личных данных сохраняется.
- Лента получает небольшие JPEG-превью до 480×360; исходные изображения не изменяются. Остальные обложки загружаются лениво.
- Неизменённая карточка и её изображение сохраняются при опросе; загрузка фото не начинается каждые пять секунд заново.
- После ввода кода используется уже возвращённый CSRF-токен без лишнего запроса. Обычный запрос имеет предел 8 секунд, начальное подключение — общий бюджет 9 секунд и кнопку повтора. Это не относится к длительной операции PDF/импорта.

Проверка на Mac в Chrome с размером iPhone 393×852: редактор 4,295 с; вход и лента из 100 тестовых карточек 3,983 с. При искусственно недоступном Mac повтор подключения появился через 8,949 с. Внешняя HTML-страница реально получена через HTTPS за 0,949 с, после чего проверены вход и закрытые API. Это измерения открытия интерфейса, а не обещание одинаковой скорости на любом операторе и не время загрузки исходного объявления.
