# Разные подачи китайского объявления

Поверх прежнего каталога добавлен отдельный слой `zh-rental-layouts-v1`: **20 семейств подачи** заголовка и описания. Это не ещё 20 каталогов по 262 144 текста. Старые ID `zh-…-v1-…`, их развёрнутые NDJSON.gz и правила подсчёта сохраняются; новая фактическая подача получает свой ID и отдельно указывает старый `baseTemplateId`.

Пользовательские примеры использованы как образцы композиции: короткая строка с emoji, цена впереди, транспорт в начале, спокойные абзацы, перечень по зонам, нумерованная карточка и небольшая заметка перед просмотром. Из примеров других городов не переносятся город, женская/студенческая аудитория, соседи, бесплатные платежи, разрешение питомцев, маршруты или регистрационные обещания.

## Семейства

| Семейство | Подача | Когда используется |
| --- | --- | --- |
| `emoji-summary` | Короткий заголовок и блоки с emoji | Общая |
| `editorial` | Редакционное вступление и связные абзацы | Подробная или история |
| `price-first` | Аренда и расходы раньше остальных сведений | Есть предоставленная цена |
| `room-by-room` | Конфигурация по зонам впереди | Есть предоставленное оснащение |
| `commute-first` | Сначала транспорт, затем квартира | Есть предоставленные метро/маршруты |
| `clean-card` | Спокойная карточка | Общая |
| `compact` | Плотные строки без пропуска фактов | Краткая или подробная |
| `bullet-board` | Объявление списком | Краткая или подробная |
| `numbered-guide` | Нумерованные смысловые разделы | Подробная |
| `budget-note` | Нейтральная заметка о бюджете | Есть предоставленная цена |
| `feature-focus` | Акцент на подтверждённом оснащении | Есть предоставленное оснащение |
| `area-layout` | Площадь и планировка впереди | Общая |
| `location-note` | Расположение и ориентиры | Общая |
| `university-reference` | Учебный ориентир и предоставленный транспорт | Есть конкретное название/данные вуза |
| `conditions-first` | Сначала условия аренды | Общая; разрешения — только если переданы |
| `calm-paragraph` | Нейтральные абзацы | Общая |
| `viewing-note` | Информация для проверки перед просмотром | Подробная или история |
| `catalogue` | Карточка с номером объекта | Есть настоящий переданный номер |
| `service-note` | Сервис агентства впереди | Есть переданная формулировка сервиса |
| `split-sections` | Две смысловые группы | Подробная или история |

Стиль `compact`, `detailed` или `story` выбирает совместимые семейства, а существующий счётчик варианта воспроизводимо перебирает их. Случайность и текущее время не используются. Для одинакового счётчика, стиля и набора подтверждённых данных получается одинаковый результат. При малом наборе данных часть специальных семейств недоступна, а результаты могут повторяться; уникальность 262 144 фактических новых описаний для одной квартиры не заявляется.

## Что сохраняется

Предоставленные `facts`, `equipment`, `conditions`, `service` и остальные непустые блоки остаются во всех режимах. Краткий стиль меняет плотность, порядок и оформление, а не молча убирает мебель, цену, залог или запреты. Крайние пробелы, маркеры разрешений/запретов и числовые значения не превращаются в противоположный смысл. Уже оформленное начало блока не получает такой же дополнительный заголовок с emoji.

В заголовке при наличии сохраняются город, планировка, площадь и цена. Дополнительный акцент выбирается из действительно переданных метро, оснащения, этажа, учебного ориентира, разрешения, номера объекта или краткого сервиса. Наличие вуза не означает разрешение студентам или близость квартиры. Наличие духовки не добавляет плиту, холодильник или микроволновую печь. Наличие кровати не добавляет отдельную спальню, двуспальный размер или вместимость.

Сервис регистрации передаётся готовой формулировкой агентства, например `抵达登记（临时居住登记）：提供办理协助。`. Сам макет не дописывает «бесплатно», «согласие владельца», выдачу визы или `包落地`. Номер вида YL26269 не создаётся автоматически: семейству `catalogue` нужен настоящий `code` из данных оператора.

## API для общего генератора

```js
getListingStyle('title', titleVariant, context)
// id, version, kind, index, style, family, label, baseTemplateId

renderListingTemplate('title', titleVariant, {
  city, layout, area, price, metro, feature, floor,
  code, university, serviceShort, permissions, style
})

renderListingTemplate('description', copyVariant, {
  location, facts, equipment, transport, conditions, service, contact,
  city, layout, area, price, metro, code, university,
  universityTransport, style
})

renderListingEquipment([
  {id: 'bedroom', items: ['床（尺寸待确认）', '衣柜（至少2件）']},
  {id: 'kitchen', items: ['烤箱']}
], copyVariant)

renderListingTemplate('tags', tagVariant, {tags: confirmedAndBrandTags})
listingStyleStats()
```

`renderListingEquipment` использует нейтральные заголовки назначения — например «休息区» и «清洁与卫浴». Они не утверждают отдельность комнаты и точное место установки прибора. Пользовательский `label` следует передавать только при подтверждённом расположении.

Короткие альтернативы `locationShort`, `factsShort`, `equipmentShort`, `transportShort` допускаются только с отдельным явным `useShortBlocks: true`. Одно значение `style: 'compact'` их не включает. Условия аренды и сервис этими альтернативами не заменяются. Ответственность за состав заранее подготовленной краткой строки остаётся у вызывающего общего генератора; текущие основные блоки по умолчанию не сокращаются.

Слой тегов сохраняет прежний проверенный словарь общих тем, все переданные фактические и брендовые теги и воспроизводимый индекс. Он не добавляет питомцев, студентов, пол жильцов или бесплатные услуги из выбранного стиля текста. Заголовок, описание и теги остаются отдельными полями: общий пост можно собрать в порядке «заголовок → описание → хештеги» без переноса тегов в середину описания.

## Совместимость и проверка

`getTemplate`, `renderTemplate`, `catalogStats` и materialized NDJSON.gz остаются интерфейсом прежнего v1-каталога. Перед подключением новой подачи к предпросмотру надо использовать `renderListingTemplate`, чтобы показывать тот же слой, что фактически применяет генератор. Старый `baseTemplateId` не должен выдаваться за ID нового оформления.

Контрольный SHA прежних результатов не изменился; сжатые файлы не перегенерированы и сохраняют свои хеши. В manifest обновлён только хеш исходного модуля, в который добавлен новый слой. Отдельные тесты проверяют двадцать семейств, сохранение всех блоков в трёх режимах, отсутствие чужих фактов, независимость номера объекта, смысловые символы условий, Unicode, нейтральную группировку оснащения и детерминированность.
