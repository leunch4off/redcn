# Локальный анализ фотографий на Mac

Сервер redcn передаёт фотографии локальной vision-модели на Mac. Телефон показывает уже подготовленный результат; устанавливать Ollama на iPhone не требуется. Используется отдельный native ARM64 Ollama с моделью `qwen3-vl:2b-instruct-q4_K_M` и адресом `http://127.0.0.1:11435`.

Это инструкция установки и эксплуатации, а не подтверждение, что приложение или веса уже установлены на конкретном Mac. Время распознавания и потребление памяти на Mac mini M2 8 ГБ нужно измерить на настоящих фотографиях. Подробности выбора модели и первичные источники: [PHOTO-VISION-RESEARCH.md](PHOTO-VISION-RESEARCH.md).

## Однократная подготовка

Нужны Apple Silicon, macOS 14 Sonoma или новее, Python 3 и свободное место. Установщик проверяет совместимость и требует не менее 6 ГиБ свободного места на этапах `install` и `pull`. Запуск уже установленной службы, остановка и статус не требуют этого запаса. Выполняйте команды из папки репозитория redcn тем Python, которым запускается сервер.

Без `--apply` helper только печатает план. Он не скачивает приложение, не запускает службу и не загружает модель:

```sh
python3 scripts/install-photo-ai-macos.py
```

На другой ОС установка с `--apply` прекращается до изменений. На Mac этапы выполняются по отдельности:

```sh
python3 scripts/install-photo-ai-macos.py --stage install --apply
python3 scripts/install-photo-ai-macos.py --stage start --apply --allow-initial-keypair
python3 scripts/install-photo-ai-macos.py --stage pull --apply
python3 scripts/install-photo-ai-macos.py --stage status --apply
```

`install` получает закреплённый официальный ZIP Ollama v0.40.13, сверяет размер и SHA-256, проверяет безопасные пути архива, подпись Developer ID, Gatekeeper и наличие ARM64 до запуска скачанного кода. Ошибка любой проверки прекращает этап. Системный каталог Applications и PATH не меняются; GUI не открывается.

`start` запускает только выделенную службу на порту 11435. При первой инициализации сам Ollama создаёт `~/.ollama/id_ed25519` и `.pub`, если ключей ещё нет; флаг `--allow-initial-keypair` разрешает именно этот шаг. Содержимое существующих ключей не нужно читать или выводить. Обычный автоматический запуск сайта новые ключи не создаёт.

`pull` отдельно загружает веса выбранной локальной модели в приватный каталог. Сообщение `model_ready` подтверждает наличие тега и поддержку изображений, но ещё не доказывает точность распознавания квартиры. Сообщения прогресса установки и загрузки весов выводятся в терминал.

## Включение в redcn

Установка Ollama сама по себе не включает анализ фотографий. Настройки redcn доступны через авторизованный API:

| Операция | Локальный редактор | Подключённый телефон |
| --- | --- | --- |
| Прочитать настройки | `GET /api/local/photo-ai` | `GET /api/phone/photo-ai` |
| Сохранить часть настроек | `POST /api/local/photo-ai` | `POST /api/phone/photo-ai` |

Локальный API требует текущий `X-Redcn-Token` редактора и допустимый Origin; телефон использует свою действующую сессию и CSRF-защиту. Токены нельзя помещать в PDF, публиковать или сохранять в этой инструкции.

Пример тела POST для подготовленной приватной службы:

```json
{
  "enabled": true,
  "model": "qwen3-vl:2b-instruct-q4_K_M",
  "endpoint": "http://127.0.0.1:11435",
  "autoApply": true,
  "maxSeconds": 600
}
```

GET возвращает текущий объект настроек; POST принимает частичное обновление этих полей. `enabled` включает локальный анализ; `autoApply` разрешает применять прошедшие правила положительные наблюдения, но не делает модель безошибочной. При `autoApply:false` признаки остаются для ручной проверки. `maxSeconds` — общий предел этапа анализа фотографий, от 60 до 1800 секунд, а не обещание длительности одного снимка.

Адрес обязательно должен совпадать с выделенной службой: `11435`. Существующие настройки могут указывать стандартный пользовательский Ollama на `11434`; установка приватного экземпляра не является разрешением менять или останавливать тот сервер. Допустим только буквальный loopback IP `127.0.0.1` или `::1`, без удалённого сервиса и облачного имени модели.

Настройки сохраняются как `photo-ai.json` в каталоге данных работающего redcn. Если файла ещё нет, поддерживается настройка через `REDCN_VISION_MODEL` и `REDCN_VISION_ENDPOINT` в окружении сервера. Сохранённый файл имеет приоритет; для обычной эксплуатации предпочтительнее настройки API.

## Автоматический запуск во время работы

Когда анализ включён и выбран выделенный endpoint 11435, runtime может запускать заранее установленный и проверенный приватный бинарник при старте сервера, сохранении настроек и перед анализом. Он не устанавливает Ollama, не загружает веса, не открывает GUI, не создаёт ключи и не переключается на облако. Для такого запуска однократная подготовка выше должна уже завершиться. Отсутствие модели или ошибка запуска должны оставлять понятный статус, а не начинать скрытую установку.

Служба получает `OLLAMA_NO_CLOUD=1`, отдельный каталог моделей, одну одновременно загруженную модель и один запрос к ней. HOME процесса не подменяется. Стандартный пользовательский Ollama на 11434 не останавливается. Ошибка или занятый чужим процессом порт не дают права завершать этот процесс. Runtime ограничивает подготовку запуска 60 секундами, включая резерв на очистку; если вызывающая операция передала более ранний deadline, применяется он. Отмена запуска очищает только новую собственную службу; уже готовая общая служба продолжает работать при отмене отдельного анализа.

## Проверка и остановка

```sh
python3 scripts/install-photo-ai-macos.py --stage status --apply
python3 scripts/install-photo-ai-macos.py --stage stop --apply
```

`status` сообщает, найдена ли собственная служба, её версию и локальные модели. `stop` останавливает только процесс/группу, ранее созданные helper и повторно проверенные по сохранённому состоянию. Остановка и чтение статуса не требуют свободных 6 ГиБ. Если анализ остаётся включённым, следующий запуск анализа может снова поднять подготовленную службу; для постоянной остановки сначала сохраните `{"enabled":false}`, затем выполните `stop`.

| Данные | Путь |
| --- | --- |
| Приложение | `~/.cache/redcn/tools/ollama/0.40.13/Ollama.app` |
| Native CLI | `~/.cache/redcn/tools/ollama/0.40.13/Ollama.app/Contents/Resources/ollama` |
| Веса модели | `~/.cache/redcn/tools/ollama/models` |
| Состояние собственной службы | `~/.cache/redcn/tools/ollama/daemon.json` |
| Журнал собственной службы | `~/.cache/redcn/tools/ollama/daemon.log` |

После успешной подготовки проверьте одну настоящую карточку с фотографиями кухни, комнаты и рабочего места. Отдельно проверьте ошибочные добавления, пропущенные предметы и повторяющиеся ракурсы. Нераспознанный предмет остаётся неизвестным; точное количество требует подтверждения. Закрытый шкаф не доказывает наличие техники внутри, а духовка не подтверждает холодильник или микроволновку.

Если проверка подписи не прошла, сохраните сообщение об этапе и остановитесь; не отключайте Gatekeeper. При тайм-ауте сначала проверьте статус/журнал собственной службы. Повторная установка не нужна для каждой карточки; повторный `pull` требуется только при отсутствии или намеренном обновлении весов.
