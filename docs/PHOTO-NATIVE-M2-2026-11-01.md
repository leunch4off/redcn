# Нативный замер фото-модели на M2 · 01.11.2026

На рабочем **Mac mini M2, 8 ГБ, macOS 26.0.1** выполнен реальный ONNX-инференс выбранной `redcn-furniture-v1` на 80 существующих проверочных изображениях Open Images. Новый изолированный ARM64 runtime сравнивался с установленным x86_64 runtime через Rosetta. Исходники пользователя и живые импорты не использовались. Настройки действующей модели и сервера не менялись.

[Полный числовой receipt](benchmarks/photo-native-m2-20261101-v25.json) содержит версии, архитектуры, результаты проверки подписей, SHA модели и библиотек, происхождение установленных ARM wheels, публичные ID кадров и метод расчёта процентилей. [Воспроизводимый скрипт](../scripts/benchmark-photo-native.py) не создаёт контроллер импорта и не запускает recovery.

## Измерения

| Измерение | ARM64 · изолированный кандидат | x86_64 · установленный runtime |
|---|---:|---:|
| Первый новый процесс: полный запуск рабочего процесса | 7,001 с | 0,747 с |
| Новый процесс на каждый кадр, 80 кадров: p50 / p95 | 0,286 / 0,330 с | 0,464 / 0,537 с |
| `_infer`, включая импорты и создание ONNX session: p50 / p95 | 0,181 / 0,224 с | 0,213 / 0,229 с |
| Максимальный RSS одного процесса, 80 кадров | 142,0 МиБ | 144,6 МиБ |
| Диагностический повтор в одном процессе: p50 / p95, 79 тёплых кадров | 0,051 / 0,061 с | 0,088 / 0,110 с |
| Максимальный RSS процесса повторной диагностики | 216,0 МиБ | 246,6 МиБ |
| Успешных результатов `review`, без автоматического применения | 80 / 80 | 80 / 80 |
| Тайм-аутов при обычной проверке | 0 | 0 |

Процентили рассчитаны методом nearest-rank. «Холодный» здесь означает новый процесс Python; системный дисковый кеш не очищался. Начальный ARM-запуск 7,001 с — отдельное реально измеренное наблюдение, его нельзя скрывать за p95. Причина начального выброса не изолирована: гипотезы о загрузке библиотек или системной проверке кода требуют отдельного измерения. Максимум остальных запусков также остаётся в исходном receipt.

Тёплая диагностика повторно вызывает настоящий `trained_photo_detector._infer`: каждый кадр всё ещё создаёт новую ONNX session, но Python-библиотеки уже загружены. Действующий провайдер запускает отдельный процесс на запрос, поэтому 0,051 с не является обещанием текущей скорости сайта. Этот результат обосновывает дальнейшую проверку одного ограниченного рабочего процесса на альбом с освобождением памяти после партии.

## Браузер, сроки и подписи

Одновременно с ARM-инференсом 20 реальных публичных кадров работал отдельный **Chrome 156.0.8078.79** с анимированной CSS/canvas-страницей. p50 / p95 полного запуска фото-процесса составили **0,365 / 0,572 с**; p95 интервала браузерных кадров — **16,8 мс**, максимальный интервал — **200,0 мс**. Это реальный Chrome, но синтетическая воспроизводимая нагрузка: пользовательский профиль, страница объявления и действующая телефонная сессия не открывались.

Три реальных рабочих процесса остановлены при искусственно коротком сроке 0,001 с; оставшихся процессов нет. Это проверка ограничителя запуска и уборки процессов, а не симуляция сетевого ожидания или доказательство точности модели. Во время обычных прогонов ни один рабочий процесс не превысил срок 12 с.

`codesign --verify --strict` подтвердил подписи Python и ARM64 ONNX Runtime, exit code 0. Существующая x86_64-библиотека ONNX Runtime вернула **exit code 1: code object is not signed at all**. Подпись производственного x86 runtime поэтому не заявляется подтверждённой. Изолированный ARM-кандидат установлен и проверен; он автоматически не включён в сервер.

## Путь запуска для рабочего провайдера

После сравнительного замера установлен отдельный постоянный runtime `tools/photo-ai-arm/venv`, не зависящий от каталога staging. [Установщик](../scripts/install-photo-native-runtime.py) использует закреплённые SHA всех десяти wheels и официальный индекс PyPI. [Проверка runtime](../cli/photo_native_runtime.py) разрешает только фиксированный интерпретатор Python 3.11.9, ARM-библиотеку ONNX Runtime и прежний SHA модели. Паспорт не может задавать исполняемый файл, аргументы или URL. Подписи проверяются реально; несовпадение версии, байтов или паспорта даёт явный отказ анализа. При отсутствии необязательной установки сохраняется прежний способ запуска.

Обновлённый `trained_photo_detector.analyze` запускает этот интерпретатор с `arch -arm64` и `-I`, проверяет архитектуру ответа и сохраняет runtime trace. Проверка целостности входит в общий срок анализа. Паспорт runtime входит в ключ кеша наблюдений; `autoApply`, `autoEligible` и автоматическое количество по-прежнему принудительно отключены. Настройки включения модели, выбранный провайдер и содержимое весов не менялись.

[Прямой интеграционный вызов настоящего `analyze`](benchmarks/photo-native-production-integration-20261101-v25.json) выполнен на Mac из x86 Python с обновлённым кодом staging и реальным публичным проверочным кадром. Выбран постоянный signed ARM runtime; дочерний процесс вернул `arm64`, `review`, `autoApply=false`. Первый запуск нового постоянного окружения занял **6,299 с**. Этот кадр с пианино вернул **0 категорий**: это успешное исполнение runtime, а не успешное распознавание предмета. Число активных импортов до/после оставалось 0. Запрос к действующему серверу или живой импорт не создавался; финальное развёртывание обновлённого кода выполняется отдельно.

В staging на самом Mac прошли 20 проверок: 3 договора публичного benchmark, 9 проверок целостности/выбора runtime и 8 тестов существующего детектора. Замеры таблицы выше сделаны до добавления проверки runtime в обёртку; их p50/p95 нельзя выдавать за повторный замер нового полного HTTP-пути.

Версии: Python 3.11.9; NumPy 1.26.4; ONNX Runtime 1.23.2 в обоих окружениях. Pillow ARM — 11.3.0, установленный x86 — 13.0.0. Версии Pillow различались, поэтому сравнение нельзя приписывать исключительно архитектуре CPU. Модель SHA-256: `650c6d96cd8b9e0c0422174467590b6ec377bc7fefa6c6ff01b0546db5392de5`.

## Численная сопоставимость и границы приёмки

Наборы найденных категорий совпали **на 80 из 80 кадров**; числовые векторы сопоставимы на всех 80. Максимальная абсолютная разница оценок и нормированных координат — **3,74 × 10⁻⁶**. Полные сигнатуры после округления до шести знаков совпали на 41 кадре; точное побитовое совпадение не заявляется.

Проверочные изображения отобраны до этого замера, их 80 ID и SHA не пересекаются с обучающей частью. До открытия каждого файла проверялись публичный S3 URL, ссылка на Flickr, автор, декларация CC BY 2.0, относительный путь и совпадение SHA/размера. Индивидуальные оригинальные landing pages повторно не проверялись; это сохранённая лицензированная метаинформация публичного набора. Фотографии не публиковались и не копировались в репозиторий.

Перед каждой фазой и каждым отдельным кадром читалось только агрегированное число активных импортов. Оно оставалось 0; общий `model-resource.lock` удерживался на время вычислений и затем освобождён. Состояние диагностической кампании не изменялось.

Замер подтверждает выполнение модели и ограничения ресурсов на реальном M2. Он **не закрывает RCN-318, RCN-213/319 или точность watermark**. Сравнение ARM/x86 не проверяет правильность распознанных объектов по разметке. [Первое обучение](PHOTO-AI-TRAINING-2026-11-01.md) ранее обнаружило существенные пропуски и ложные находки; модель остаётся источником подсказок для ручной проверки.
