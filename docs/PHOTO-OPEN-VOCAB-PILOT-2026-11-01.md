# Открытый словарь предметов: реальный пилот YOLO-World · 01.11.2026

На Mac mini M2 с 8 ГБ выполнены экспорт и настоящий ARM64-инференс **YOLO-Worldv2-S**, затем сопоставление с существующей `redcn-furniture-v1` на тех же 80 публичных проверочных кадрах Open Images. Кандидат лучше на этом малом наборе, но **не прошёл приёмку для автоматического заполнения описаний**. Настройки действующего провайдера, сервер, импорты и пользовательские фотографии не менялись.

Ключевой результат: холодильник существующая модель не нашла ни разу из пяти размеченных экземпляров; кандидат нашёл четыре. Для пианино осталось пять пропусков из шести. Кухонные шкафы, буфеты и письменные столы по-прежнему распознаются ненадёжно. Нельзя заявить распознавание «всей мебели» или идеальную точность.

## Измерения

| Измерение | Прежняя YOLOX Nano, 416 px | YOLO-Worldv2-S, 640 px |
|---|---:|---:|
| TP / FP / FN на проверенных положительных парах | 37 / 20 / 134 | 82 / 28 / 89 |
| Условная точность TP/(TP+FP) | 64,9% | 74,5% |
| Полнота по размеченным объектам | 21,6% | 48,0% |
| Обработка кадра p50 / p95 | 0,0318 / 0,0382 с | 0,2312 / 0,3088 с |
| Первый кадр нового процесса | 0,0622 с | 13,8128 с |
| Максимальный RSS процесса | 163,6 МиБ | 354,0 МиБ |
| Полный процесс: 80 кадров + 5 повторов | 3,075 с | 33,714 с |
| Импорт Torch / CLIP при инференсе | нет / нет | нет / нет |
| Попыток сетевых соединений | 0 | 0 |

Это диагностический **один процесс и одна ONNX session на 80 кадров**, а не 80 новых процессов и не время HTTP-импорта объявления. Системный файловый кеш не очищался. Процентили — nearest-rank, p50 — медиана. Время кадра включает чтение, подготовку, ONNX и декодирование/NMS. Пять дополнительных тёплых повторов исключают декодирование; они отдельно сохранены в JSON и не заменяют основную метрику.

Начальные **13,813 с** кандидата включают первый импорт OpenCV внутри подготовки изображения, чтение/resize, первый ONNX-вызов и декодирование. Вклад этих частей отдельно не измерялся; причины выброса нельзя приписывать конкретной библиотеке или macOS. Один холодный пример не является p95 запуска. Прогрев и ограниченный процесс на альбом могут перенести/сократить повторные расходы, но требуют отдельной проверки пользовательского пути.

Порог заранее фиксирован: **score 0,35**, сопоставление **IoU 0,5**, class-wise NMS **0,45**, максимум 200 кандидатов. Перед каждым кадром проверяются общий ресурсный замок, отсутствие активного импорта и срок эксперимента. Во время замера другие агенты освободили тяжёлую нагрузку Chrome. Ни одного действующего импорта не создавалось.

Неизвестная/неразмеченная категория **не считается отсутствующей**. Проверенных отрицательных пар — **0**: условная точность не измеряет ложные находки на фотографиях без данного предмета и не является общей точностью системы. Для посудомоечной машины нет ни одной пригодной проверочной пары. Один размеченный шкаф не подтверждает 100% точность класса. Ни одна категория не прошла существующий статистический gate.

Это существующий, ранее использованный validation-набор: 134 тренировочных кадра отделены от 80 проверочных по ID и SHA, но новая слепая выборка не собиралась. Таксономия и пороги не подбирались по результату этого прогона. Метаданные набора содержат происхождение S3/Flickr и CC BY 2.0; индивидуальная перепроверка каждой исходной страницы лицензии не выполнялась. Исходные изображения, HTML, cookies, договоры и личные данные не переносились в репозиторий.

## Что именно выполнено

1. Официальный checkpoint YOLO-Worldv2-S и OpenAI CLIP ViT-B/32 проверены по закреплённым SHA.
2. Официальный OpenAI CLIP загружен из закреплённого исходного commit, что проверяется через `direct_url.json`; одноимённый fork отвергается.
3. Один раз вычислены 21 английский prompt embedding; размер `[1,21,512]`, порядок классов и конечность значений проверены.
4. Фиксированный классификатор экспортирован в ONNX `[1,3,640,640] → [1,25,8400]`, только один вход-изображение. **Обучения весов/добавления собственных параметров не было.**
5. ARM64-проверка запускает только NumPy/Pillow/OpenCV/ONNX Runtime. Torch и CLIP в процессе отсутствуют. Модель и encoder не добавлены в рабочие настройки.
6. Шесть проверок протокола прошли локально и на самом Mac: масштабирование boxes, malformed output, неизвестные классы, слабые/вырожденные находки, блокировка сети и отказ от подмены CLIP.

Экспорт выполнен отдельным x86_64 процессом через Rosetta: **45,570 с**, импорты **37,450 с**, одноразовое кодирование prompts **4,274 с**, ONNX-экспорт **2,502 с**, максимальный RSS **1,527 ГиБ**. Первый технический запуск остановился до загрузки весов из-за отсутствующего `wcwidth` у `ftfy`; зависимость установлена только в изолированное окружение, затем экспорт повторён. Это ошибка подготовки окружения, не качество распознавания.

Исходная модель содержит **12 759 880 параметров**; после fuse экспортёр сообщил **12 749 288**. Размер ONNX **51 274 854 байта**. SHA-256:
`eb56e6e04067350e6bb4c9603a4664707ec7620f3a3dda81c1ddd8fd9d580bba`.

Версии экспорта: Python 3.11.9, Torch 2.2.2, torchvision 0.17.2, NumPy 1.26.4, ONNX 1.17.0, Ultralytics 8.4.197, OpenAI CLIP 1.0. Инференс ARM64: Python 3.11.9, NumPy 1.26.4, Pillow 11.3.0, ONNX Runtime 1.23.2, OpenCV 4.11.0.86, CPUExecutionProvider, 2 intra-op / 1 inter-op threads. MPS/GPU не использовались.

Установка/загрузка делается отдельно и явно; сам эксперимент блокирует сетевые соединения. Публичный manifest закреплён SHA `dc53ecb5e38e0a87e2fe6084c1e6738ab33c3c7f5016b9b272e7f047b49151ee`; исходный training manifest — `33b741b0f9162379ae58c9cd23dd03ee73c9fc9c5a875abf22f7dcfaf0416e0c`. Старый числовой отчёт не перезаписывается. Для повторного экспорта требуется новый изолированный каталог с отдельно проверенными весами; нельзя молча заменить результаты.

В репозитории находятся только исходники и очищенные измерения. Веса, raw-фотографии и prompt NPZ остаются в отдельном кеше.

## Решение

**Сохранить кандидата как изолированное исследование, не включать автопубликацию.** Позитивный результат для холодильника/микроволновки/дивана обосновывает следующий ограниченный review-пилот, но ошибки у шкафов и низкая полнота пианино/столов остаются существенными. Сначала нужны независимые фотографии с отрицательной разметкой, больше шкафов/кухонных фасадов/столов/пианино, разбор конфликтов близких классов и отдельные пороги по классу. Вытяжка, компьютер, watermark, скрытая техника, исправность и подсчёт одного предмета на разных ракурсах здесь не проверялись. Отсутствие находки всегда остаётся «не установлено по фото», а не «предмета нет».

Постоянный resident encoder не требуется: фиксированные prompts уже встроены в ONNX. Это экономит память относительно VLM, но не превращает словарь prompts в доказательство распознавания. Встраивание в сайт, crop и автодобавление в описание в этом пилоте не выполнялись.
