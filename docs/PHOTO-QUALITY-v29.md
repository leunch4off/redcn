## Очередь разметки в приложении

Модули: `cli/photo_training.py`, `cli/photo_training_api.py`, `web/photo-training.mjs`.

Для сохранённой карточки доступна отдельная панель **«Разметка фото для обучения»**. Она загружает оригинал через аутентифицированный запрос, показывает категорию, позволяет обвести рамку мышью/тачем и уточнить нормализованные координаты. Необязательный ID предмета сохраняет явно подтверждённую связь между ракурсами; наличие связи не означает точного общего количества предметов в квартире.

Состояния сохраняются раздельно:

| Состояние | Смысл | Может попасть в учебный экспорт |
|---|---|---|
| `pending` | Находка ожидает проверки | Нет |
| `present` | Предмет виден, рамки указаны | Только после явной полной проверки категории |
| `absent` | Человек проверил отсутствие данной категории на оригинале | Только после явной полной проверки; рамок быть не должно |
| `unknown` | По этому фото нельзя сделать вывод | Нет |
| `rejected` | Предложенная моделью находка отклонена | Нет; это не отрицательная обучающая метка |

Даже прежнее подтверждение находки в карточке поступает в очередь как `pending`: оно само по себе не подтверждает рамку, полноту разметки или право использовать фото в обучении. Предсказания и уверенность модели не превращаются в учебную истину.

Оператор задаёт общую группу квартиры, часть `train` / `calibration` / `test`, подтверждает проверку повторных ракурсов и право использования текущих оригиналов. Разрешение связано с конкретным набором SHA; при замене или добавлении оригинала оно требует подтверждения заново. Каждый save передаёт `rights.photoIds` из загруженной очереди: изменение набора оригиналов даёт HTTP 409 даже при прежней ревизии разметки. Старая открытая форма не может автоматически разрешить использование добавленного фото. Новые записи фиксируют автора из серверного контекста и время решения, клиент не задаёт автора. Сохраняются ревизии; конкурентная запись со старой версией получает HTTP 409.

API `photo-training/<cardId>` вызывается после существующей аутентификации:

- `GET` — очередь, происхождение предложений, текущая ревизия и оригиналы этой карточки. Отдельная база разметки не создаётся при чтении.
- `POST {action: "save", document, expectedRevision}` — ручное сохранение.
- `POST {action: "export"}` — приватный JSON с проверенными метками этой карточки. Непроверенные строки остаются в очереди.

Фото другой карточки, неверный SHA/ID, неопределённость, подтверждённая без полной проверки метка и конфликтующая отрицательная рамка отклоняются. Экспорт заново проверяет байты оригиналов. Фоторазметка не переписывает текст объявления, характеристики квартиры или выбранную модель.

## Приватный корпус и происхождение

`scripts/photo-corpus.py export` объединяет только явно выбранные карточки и создаёт новый приватный каталог: изображения с исходными байтами, manifest с SHA, группой квартиры, split, рамками, явными отрицательными категориями, версией проверки и автором решения. Каталог имеет режим 0700, файлы — 0600. Существующий путь не перезаписывается. При незавершённом копировании остаётся маркер `INCOMPLETE`, успешный manifest записывается последним.

```bash
./.venv/bin/python scripts/photo-corpus.py export \
  --cache ~/.cache/redcn \
  --card-id ID_ПЕРВОЙ_КАРТОЧКИ --card-id ID_ВТОРОЙ_КАРТОЧКИ \
  --output /новый/приватный/каталог
```

Одна группа квартиры не может находиться в разных частях. Один SHA не может принадлежать разным группам. Противоречивые метки одного оригинала отклоняются. Сопоставление пережатых копий, кропов и перевыставленных объявлений требует человеческой проверки; инструмент не выдаёт совпадение хешей за полный поиск близких дублей. Поэтому manifest явно содержит `independenceVerified=false` и `automaticAcceptance=false`.

Отзыв разрешения исключает текущие строки из новых экспортов. Он не удаляет влияние из уже обученных весов и не отзывает ранее вручную сохранённые копии manifest автоматически; такой архив нельзя считать вновь разрешённым источником без сверки текущего согласия.

## Замороженные пороги и отложенная проверка

`cli/photo_calibration.py` и подкоманды `freeze` / `evaluate` принимают явные предсказания детектора. Это измеритель разметки и выдачи, без загрузки или установки модели.

1. `freeze` требует отдельные непересекающиеся `train`, `calibration`, `test` и использует для выбора порога **только calibration**. Предсказания другой части или пропущенного оригинала отклоняются. Квитанция связывает модель, полный корпус, политику, выдачу и пороги через SHA.
2. Для каждой категории выбирается порог из заранее заданной сетки. Если поддержки недостаточно, порог остаётся `null`, категория сохраняется в режиме проверки человеком.
3. `evaluate` проверяет новый массив выдачи **только test**, используя уже зафиксированные пороги. Изменение корпуса, весов, политики или неподтверждённая правка квитанции блокируют оценку.
4. CLI записывает маркер использования конкретной связки corpus/model/calibration. Повторный запуск этой связки требует `--diagnostic` и явно так помечается. Это локальный журнал воспроизводимости, а не доказательство того, что человек никогда не видел test-фото.

```bash
./.venv/bin/python scripts/photo-corpus.py freeze \
  --manifest private-corpus/manifest.json --predictions calibration-predictions.json \
  --model-sha SHA256_ВЕСОВ --output frozen-calibration.json

./.venv/bin/python scripts/photo-corpus.py evaluate \
  --manifest private-corpus/manifest.json --predictions test-predictions.json \
  --model-sha SHA256_ВЕСОВ --frozen frozen-calibration.json --output heldout-report.json
```

Предсказания имеют вид объекта `{SHA_ОРИГИНАЛА: [{category, score, xyxy}]}`. Пустой список означает, что детектор завершил обработку и ничего не нашёл. Отсутствующий ключ не считается таким результатом. Формат рамок — нормализованный `xyxy`; очередь оператора хранит `x, y, width, height` и преобразует его при экспорте.

Метрики считают однозначное сопоставление рамок при IoU ≥ 0,5. Лишняя рамка — FP, пропущенная — FN; неизвестная категория на изображении исключается из TP/FP/FN. Действующий статистический критерий сохранён: TP ≥ 75, не менее 20 проверенных изображений, не менее 20 проверенных отрицательных изображений, нижняя граница Wilson 95% для precision ≥ 0,95, recall ≥ 0,5. Отчёт показывает показатели отдельно для каждого класса и **не устанавливает веса**. Реальная независимая разметка и проверка runtime требуются дополнительно.

### Последующая проверка сохранения ручных решений и готовности экспорта

После широкого прогона отдельно проверены и исправлены две ошибки: устаревшая картинка в IndexedDB могла стереть решения для неизменённого серверного оригинала; повторный анализ того же SHA с пустым ответом скрывал подтверждённые человеком строки и удалял их evidence. Обе ошибки воспроизведены в настоящем браузере на синтетических данных до исправления. Изменения `web/photo-ui.mjs` и `web/media-core.mjs` выполнены в рамках общей интеграции RCN-355/361; фоторазметка для обучения и рабочие веса при этом не менялись.

На свежей сборке прошли **5/5 focused browser-тестов за 12,144 с**: четыре сценария [`test_photo_cache_decisions_browser.py`](../tests/test_photo_cache_decisions_browser.py) и `test_all_formats_wait_for_inflight_photo_analysis_before_their_first_save` из `test_presentation_browser.py`.

- Сохранённые `confirmed` с количеством и `rejected`, связанные с SHA B, переживают гидратацию старой кешированной картинки A, когда текущий серверный оригинал всё ещё B. Проверены интерфейс и настоящее сохранение карточки.
- Если настоящий оригинал на сервере изменился на C, решения для B не переходят на C.
- Если повторный анализ неизменённого B вернул пустой список, сохраняются только прежние подтверждённые/отклонённые человеком строки; неподтверждённая догадка модели исчезает. Проверены галочки, количество, сохранённые характеристики и `photoEvidence`, ручное описание остаётся прежним. Сохранённое решение явно помечается `operator-kept`.
- Если полностью подготовленный B заменён на C непосредственно перед экспортом, в пределах пяти секунд выполняется новый запрос canonical metadata и загрузка C. Проверка декодирует изображения из скачанного HTML: он содержит цветной растр C, а не B с новой квитанцией.
- HTML, вступительная карточка и настоящий PDF дожидаются незавершённого анализа перед первым сохранением источника; итоговые материалы имеют одну текущую ревизию.

Это отдельная последующая регрессия: её результаты и SHA лога добавлены в JSON-сводку отдельно от прежних Node/168 browser-прогонов. Эти пять сценариев не выполняют настоящее обучение или оценку качества модели.
