# redcn v26 · проверка и завершение предыдущего обновления

Обновление собрано из сохранённой рабочей копии v26. До этого рабочий каталог Mac и ветка `feature/rcn-v8-knowledge-photos` оставались на v25 (`439b187`); в рабочем каталоге отдельно было исправлено отображение десятичной цены в заголовке. Этот выпуск объединяет подготовленные изменения и исправления, найденные при повторной проверке.

## Рабочие изменения

- **Доступ владельца.** Приватные операции привязаны к отдельному рабочему пространству, а публичная HTML-оболочка больше не содержит его токен. Вход на Mac выполняет локальный launcher; перезагрузка сохраняет вход. Приглашённые телефоны сохраняют свои сессии и назначенные роли. Это один владелец общей библиотеки и приглашённые участники, а не несколько независимых библиотек в одной базе.
- **Мебель на нескольких ракурсах.** В редакторе и на телефоне можно открыть оригинал, выделить предмет, связать одинаковый экземпляр на разных снимках и подтвердить видимое количество. Ошибочные связи и конфликтующие ревизии показываются явно. Автоматическая модель не объявляет количество предметов точным инвентарём квартиры.
- **Текст и ИИ.** Цена `8.5W` сохраняется при очистке названия и принимается проверкой подтверждённой цены перед китайскими иероглифами. Усилены проверки коммунальных платежей, отрицаний, неопределённости и близости к метро. Комиссия по-прежнему исключается из клиентских материалов. Новая команда статуса различает настройки, наличие файлов и реально применяемую политику фотоанализа.
- **Мобильный редактор.** Фокус учитывает видимую область и нижнюю навигацию. Добавлен журнал фактических проверок телефона и китайской редактуры: оператор записывает результат, журнал сохраняет его как сообщение оператора и не закрывает roadmap автоматически.
- **Наблюдения публикаций.** Форма сохраняет датированные просмотры, теги и характеристики поста; сравнение учитывает сопоставимость и недостаточность данных. Ранжирование не выдаётся за доказанный причинный эффект тега.
- **Источники и география.** Добавлены обезличенные структурные примеры ЦИАН/Авито, справочные основания для станций, девять текущих и один исторический факультетский адрес, проверка переездов и закрытых подразделений, привязка опубликованных координат к конкретным зданиям. Подключаемый маршрутный адаптер различает пеший/автомобильный расчёт и общественный транспорт.
- **Перенос и подготовка выпуска.** Подготовлены шифрованная ручная облачная копия, выбор собственного браузера для уведомлений, перенос синтетического архива на отдельный macOS runner и артефакт Sites после CI. Их наличие не включает облачную отправку, не выбирает получателя и не публикует Site.

## Ошибки, найденные повторной проверкой

| Ошибка | Исправление |
| --- | --- |
| Desktop-редактор экземпляров загружал защищённое фото обычным `<img>` без токена | Авторизованная загрузка, временный blob URL, отмена устаревшего запроса и освобождение URL |
| После первого сохранения карточки блок мебели мог продолжать просить сохранить её | Обновление фотопанели после получения нового ID |
| `8.5W独立两居` ошибочно распознавалось как неподтверждённое число | Проверка суффикса W учитывает соседние китайские символы и по-прежнему отклоняет изменённую цену |
| Статус фото-ИИ расходился с реальной конфигурацией и обязательной проверкой результатов | Используется общий валидатор, учитывается настройка окружения и фактическое запрещение автоприменения для мебельной модели |
| Неправильная форма ответа маршрутизатора вызывала исключение программирования | Строгая проверка summary/legs/status, понятный отказ и возможность следующей попытки |
| Некорректный Unicode-токен мог обрывать HTTP-запрос | Проверка формата до сравнения, штатный отказ доступа |
| Проверка службы считала дополнительное поле версии признаком чужого сервера | Проверяется обязательная идентичность приложения и хранилища, дополнительные поля здоровья допустимы |
| Launcher требовал исправный глобальный Python даже при рабочей `.venv` | Существующая среда проекта проверяется и используется независимо от постороннего Python |
| `npm run dev` не отдавал часть новых модулей, останавливая загрузку интерфейса | Разрешены все проверяемые публичные JS/CSS внутри `web/`, приватные пути закрыты; проверяется полный граф импортов |
| Тест дизайнера путал первый нарисованный canvas с повторной отрисовкой после фото | Отдельно проверяются первый canvas и завершённый canvas с фото, без произвольной задержки |
| Подтверждения выпуска могли смешать задания разных CI run | Привязка к выбранному run, PR и точному размеру артефакта; hosted Mac отличается от self-hosted |

## Проверки и установка

Точные выполненные команды, результаты, SHA и границы проверок записываются в `docs/VERIFICATION.md`. Проверочные серверы используют временные базы и синтетические карточки. Сырые страницы, рабочие фотографии, договоры, cookies, веса моделей и приватная диагностическая кампания в Git не добавляются.

Рабочая папка на Mac: `~/Downloads/redcn-v5`. После обновления открыть существующий сервер с входом владельца:

```bash
cd ~/Downloads/redcn-v5
./.venv/bin/python scripts/open-local-workspace.py
```

Проверить ИИ и ответ сервера без запуска моделей или обучения:

```bash
cd ~/Downloads/redcn-v5
./.venv/bin/python scripts/ai-status.py --server
```

`ВКЛЮЧЕНО` обозначает разрешение функции. Наличие файлов, выбранный адаптер и живой worker — отдельные факты; отсутствие процесса в простое ожидаемо. Новая команда не выдаёт записанный этап обучения за доказательство работающего процесса.

## Границы результата

Физический iPhone, независимый китайский редактор, реальная статистика просмотров, полная точность мебели/водяных знаков и живой импорт защищённого источника имеют отдельные критерии. Они не заменяются браузерными или синтетическими тестами. Один обезличенный вариант ЦИАН не равен нескольким независимым схемам. Подтверждение отдельных линий и названий не означает полную официальную сверку московского справочника.

Текстовые модели остаются источником проверяемых черновиков. Сохранённые измерения не показали редакционной готовности адаптера; новые веса автоматически не принимаются. Облако, внешний канал доставки и публикация Sites требуют собственной настройки и фактической проверки. Текущий выпуск устанавливает код на Mac и сохраняет его в существующей ветке GitHub.
