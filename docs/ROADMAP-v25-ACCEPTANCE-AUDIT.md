# Аудит приёмки Roadmap: фактический проход v25

Дата: 1 ноября 2026 года. Исходный реестр прохода — plan.json версии 21: **334 задачи, 296 done и 38 planned**. Текущий реестр версии **22: 334 задачи, 304 done и 30 planned**. В v25 приняты восемь исходно открытых ID: **RCN-115, RCN-137, RCN-139, RCN-215, RCN-263, RCN-272, RCN-317 и RCN-330**. Исходный срез — v24, локальное дерево 5b528e0, соответствующее установленному дереву GitHub 039673b. Здесь учтены новые исходники и результаты v25. Окончательный SHA и установка фиксируются журналом выпуска; этот документ не меняет plan.json, критерии, зависимости или ID.

Применяется [политика Roadmap](ROADMAP-POLICY.md): принимается весь исходный критерий. Фикстура не заменяет прямо требуемые физический iPhone, другой Mac, живой импорт или носителя языка. К узкому критерию также нельзя добавлять новое условие: API не обязателен для обычного TTL-кеша, а задача сравнения моделей не требует пригодного к публикации победителя. Все исходные ID сохраняются.

Аудит опирается на исходники, сохранённые отчёты, независимые синтетические тесты и отдельно указанные результаты основного контроллера на Mac. Cookies, auth-файлы, договоры, исходные фото и HTML пользователя для аудита не читались; реальные импорты не создавались. Кампания ImportDiagnostics и её tg.zip не используются как готовый результат и не изменялись.

## Дефекты, устранённые после независимой проверки

1. Кнопки кеша новой строки не включались после выбора транспорта. Доступность теперь обновляется вместе с режимом и занятостью запроса; возврат к unknown не включает их поздним ответом.
2. Удаление предыдущей строки во время lookup позволяло записать ответ по старому индексу. Ответ применяется к текущему индексу того же объекта при неизменных полях; отдельный нативный сценарий прошёл.
3. Английский заголовок проходил с китайским описанием. Язык заголовка проверяется отдельно с допустимыми именами станции/ЖК; независимый пример теперь блокируется.
4. Inspect выдавал квитанцию для несовместимого столбца до ошибки restore. Доверенные схемы/типы/ограничения и нужные документы проверяются в отдельной временной базе до квитанции. Пример learning/examples с columns=['not_a_column'] теперь отвергается.
5. Backup терял альтернативные оригиналы/паспорт выбора. Теперь сохранены доступные байты/подрезки/алиасы/решение, неполученные недоступные URL не требуются. Повреждение сохранённого варианта вызывает ошибку; карточка и решение входят в транзакцию четырёх баз, конфликтующий выбор той же группы не перезаписывается. Разные исторические группы одного основного URL переносятся раздельно; паспорт связан с photoItems карточки, legacy-карточка без группы чужой выбор не наследует.
6. Разные URL одного платформенного photoId могли считаться разными фото. Группировка и picture/source/img-сценарии включены в финальную фотоцепочку; локальный DOM-хеш не объявляется платформенным ID.

В повторной независимой проверке обновлённого backup-кода обхода авторизации Mac, выхода ZIP за разрешённые пути, подмены выбранных байтов и перезаписи существующей рабочей базы не обнаружено. Это заключение о проверенном коде/тестах, не обещание отсутствия любых будущих ошибок.

## Решение о завершении прохода

В plan.json v22 приняты **RCN-115/137/139/215/263/272/317/330**: восемь закрытий, итог **304 done / 30 planned** из 334. Доказательства завершённых городских данных, нативного фото-runtime и общей цепочки изображений получены и отражены выше; прежние промежуточные PENDING-состояния больше не действуют. Постоянный домен и официальный сервис TUNA уже существуют, а физическая сквозная приёмка reboot/PWA по RCN-247 остаётся незавершённой. Другие ID оцениваются только по собственному исходному критерию; счётчик не цель приёмки.

Утверждение «весь Roadmap выполнен» пока не соответствует доказательствам: остаются реальные источники, независимые данные/редактура, выбранные внешние настройки и прямо требуемые физические проверки. При этом отрицательный результат сравнения, готовый TTL-кеш и честный каталог источников — завершённая работа в своём объёме; их не следует искусственно держать открытыми из-за более широких соседних задач.

Итоговый handoff должен назвать принятые ID и проверенный SHA, обязательные проверки/CI, состояние установленного сервера/публикации, реальные измерения скорости и точные оставшиеся условия. Слова «идеальная модель», «все фото», «все улицы/вузы» соответствующие измерения не заменяют.
