# Индексируемый каталог китайских шаблонов

Каталог содержит **262 144 схемы заголовка, 262 144 схемы описания и 262 144 схемы набора тегов**. Это проверяемые композиции небольших языковых блоков, а не утверждение о 786 432 вручную написанных текстах, словах или отдельных хештегах.

В `web/template-catalog.mjs` находятся 128 базовых языковых элементов: 40 вариантов формулировок заголовка, 40 заголовков разделов описания и 48 общих тематических тегов. Каждый вид шаблона имеет шесть независимых осей по восемь вариантов: `8⁶ = 262 144`.

- Заголовок: вступление, формулировки планировки/площади/аренды, выбор подтверждённой детали (метро или оснащение) и порядок блоков. Все характеристики сохраняются в описании; заголовок выбирает часть из них, чтобы не перегружаться.
- Описание: пять независимых наборов заголовков фактических разделов и восемь порядков расположения. Короткая разметка зависит от выбранного индекса; количество не раздувается за счёт одной только пунктуации.
- Теги: шесть непересекающихся тематических семейств — Москва, Россия, аренда, жильё, повседневная жизнь и обсуждение объявления. Схема даёт шесть общих тегов, к которым добавляются переданные генератором подтверждённые теги метро, планировки, оснащения и бренда. 262 144 означает комбинации наборов; самих общих тегов 48.

Счётчик пользователя переставляется по взаимно однозначному преобразованию индексов: соседние нажатия меняют несколько осей, а не одну запятую. Не используются невидимые символы, порядковые номера в публикации или разные эмодзи для искусственной уникальности.

## Факты и ограничения

Рендерер принимает подтверждённые строки из общего генератора. Отсутствующее значение удаляется вместе с подписью. Шаблоны сами не добавляют ремонт, наличие мебели, разрешение животных/детей, студенческую аудиторию, расстояние до метро или условия залога. Блок помощи с регистрацией и контактный блок передаются целиком и не меняют своего смысла.

Количество относится к полным схемам. Если у квартиры нет части полей, разные схемы могут дать одинаковый короткий результат. Каталог не обещает 262 144 существенно разных объявлений для пустой карточки. Общие теги — рабочие тематические формулировки; их частота и популярность на конкретной платформе здесь не заявляются.

## API

```js
getTemplate('title', ordinal) // id, kind, index, skeleton, axes
renderTemplate('title', ordinal, {city, layout, area, price, metro, feature})
renderTemplate('description', ordinal, {location, facts, equipment, transport, conditions, service, contact})
renderTemplate('tags', ordinal, {tags: confirmedTags})
catalogStats()
```

Страница не загружает сотни тысяч строк при запуске: любой индекс разрешается локально из компактного каталога. `CATALOG_SIZE` и `TEMPLATE_KIND_COUNT` равны 262 144. Индексы циклические, идентификатор `zh-<kind>-v1-<ordinal>` воспроизводим.

## Полная проверка и развёрнутые файлы

```bash
node scripts/audit-template-catalog.mjs
node scripts/audit-template-catalog.mjs --export-dir /path/to/catalog
```

Проверяется каждый индекс всех трёх каталогов: уникальность схем, уникальность текстов на полной фиксированной карточке после удаления пунктуации, сохранение цены/площади/условий, отсутствие незаменённых подстановок. Для тегов сравниваются нормализованные множества, поэтому одна перестановка тех же тегов не считается новым набором.

В режиме экспорта создаются `title.ndjson.gz`, `description.ndjson.gz`, `tags.ndjson.gz` и `manifest.json` с количеством и SHA-256 воспроизводимых развёрнутых строк. Экспорт — технический способ получить все готовые схемы; он не требуется для обычной работы генератора.

Готовые файлы уже находятся в `data/template-catalog/`: 262 144 строки каждого вида, всего 786 432. Суммарный сжатый размер около 12,8 МБ. Manifest также содержит SHA-256 сжатых файлов и исходного модуля, чтобы изменение правил не осталось скрытым за прежним счётчиком. Обычные тесты проверяют эти хеши; полный аудит дополнительно проходит все строки и нормализованные тексты.
