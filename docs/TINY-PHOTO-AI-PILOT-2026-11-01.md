# Лёгкий фото-детектор для redcn: пилот 01.11.2026

Найдены готовые модели, обучение с нуля не требуется. Для проверки выбран официальный YOLOX-Nano ONNX: 0,91 млн параметров, файл 3 659 407 байт. Следующий вариант YOLOX-Tiny: 5,06 млн, 20 219 662 байта. Это не утверждение «самая маленькая модель в мире»: автор NanoDet также предлагает INT8-варианты около 1 МБ.

## Проверено на рабочем Mac

Изолированный запуск в `/tmp/redcn-nano-pilot.4ckG7a`, установленный Python x86_64 через Rosetta, ONNX Runtime 1.23.2, CPUExecutionProvider, два вычислительных потока. Это реальный M2, но **не нативный ARM/CoreML benchmark**. Настройки redcn, кампания импортов и Qwen не менялись; рабочие фотографии не читались. Пилот не запускает сервер и не добавляет объявления.

## Наблюдения качества

- На COCO 139 Nano предложил телевизор (score 0,899), стулья (две рамки 0,665/0,614), обеденный стол (0,457). Рамки стульев не превращаются в общее количество по квартире.
- На кухне Nano предложил только стол/рабочую поверхность (0,531), пропустил видимые приборы. Tiny предложил духовку (0,478), не предложил мойку.
- Оба варианта ошиблись на крупном плане дивана с кошками: предложили кровать (0,532/0,475). Поэтому автоматическая публикация результатов **не принята**.

Это проверка запуска на трёх публичных изображениях, не размеченная независимая оценка качества. COCO pretraining мог включать близкие примеры. Предмет не обнаружен = неизвестно, а не «предмета нет». Score детектора не является откалиброванной вероятностью.

## Как подключать к сканированию

1. После сохранения оригиналов в `photo_store` поставить отдельную ограниченную задачу детектора. Сохранять одну сессию на альбом, не загружать веса заново для каждого фото. Один worker, общий deadline, отмена; карточка остаётся доступной во время обработки.
2. Ключ кеша: SHA оригинала + SHA модели + версия preprocessing/порогов. У каждой находки сохранять оригинал, рамку, класс, score и версию модели.
3. Передать находки в существующий `listing_photo_inventory` отдельным провайдером. Его текущий `_positive` принимает только Ollama; нельзя маскировать новый детектор под Ollama или обходить проверку доверия.
4. Пока качество не принято, показывать рамки и подтверждение/отклонение в блоке мебели. Для описания использовать только подтверждённые признаки. Сомнительные, неподдерживаемые и невидимые предметы пропускать; исходный текст может давать отдельное подтверждение со своим источником.
5. Генератор RU→ZH получает обычные канонические признаки redcn, например fridge→冰箱 и sofa→沙发. Детектор не пишет объявления, условия регистрации или разрешение животных.

## Собственная специализированная модель

Готовые COCO-веса покрывают кровать, диван, стул, стол, ТВ, ноутбук, духовку, СВЧ, мойку и холодильник. В них нет отдельных классов шкафа, рабочего стола, стиральной/посудомоечной машины, вытяжки, варочной панели, пианино. Для этих классов нужна **дообученная модель**, а не дополнение списка слов к готовому детектору.

Практичный путь — сравнить NanoDet-Plus и YOLOX на разрешённом размеченном корпусе квартир, дообучить компактную основу под 20–30 нужных классов. Начальный ориентир сбора — 500–1500 разных фото; это не гарантия достаточности для всех классов. Разделять train/validation/test по квартирам, включать сложные и отрицательные примеры: монитор/ТВ, духовка/СВЧ, шкаф/холодильник, кровать/диван, стиральная/сушильная машина. Пороги выбирать на validation и проверять precision/recall отдельно по каждому классу на отложенных квартирах. Высокий порог сам по себе не доказывает точность.

Обучение можно выполнять отдельно; на Mac остаётся компактный ONNX/CoreML inference. Экспорт/INT8/CoreML принимаются повторной проверкой качества и памяти. До этого модель работает только как помощник проверки. Размер кровати, исправность, бренд без читаемой маркировки и наличие скрытых приборов не выводятся из общих объектов.

## Код и воспроизведение

`cli/tiny_photo_detector.py` — самостоятельный пилот; `tests/test_tiny_photo_detector.py` — 8 адресных проверок декодирования, NMS, границ фото, отрицательных выводов и SHA весов. Веса проверяются до загрузки runtime. Автоматической установки зависимостей/скачивания/включения нет. В production pipeline модуль пока не подключён. Roadmap по полной точности фото-ИИ остаётся открытым.

```sh
python cli/tiny_photo_detector.py --variant nano --model /path/yolox_nano.onnx --photo /path/allowed-photo.jpg --repeat 5
```
