# Полная приватная копия рабочей базы

В редакторе Mac откройте «Настройки → Резервная копия всей рабочей базы». Скачивание запускается только кнопкой. Проверка выбранного ZIP показывает число карточек, фотографий, вложений, версий материалов, правил и учебных примеров, а также SHA-256 всего комплекта. Проверка не восстанавливает карточки и не меняет рабочую базу. Для этих двух маршрутов требуется локальный токен редактора Mac; даже роль владельца на телефоне не даёт доступ к копии всей базы.

Комплект `redcn-private-workspace`, версия 1, содержит:

- Все сохранённые карточки с новыми ID при восстановлении; ссылки между карточками и из истории редактора переназначаются вместе.
- Приватные статусы и заметки, вложения, договоры и планировки, все сохранённые версии HTML/PDF/intro/outro с их снимками дизайна.
- Все известные оригиналы фото, включая исходный альбом, если выбранная подборка короче; сохранённые подрезки и их проверки.
- Журнал ручной привязки видимых предметов к снимкам: версии, области изображения, подтверждённые связи и пересчитанная контрольная сумма после переназначения карточек.
- Общий дизайн, логотип и аватар с оригинальными и подготовленными байтами; личные правила, настройки профиля, журнал предложений словаря.
- Серверную историю редактора, подтверждённые и ожидающие проверки учебные примеры, решения по ним и сохранённое разделение train/holdout.

Данные только в localStorage конкретного браузера в серверную копию не входят: сохраните их штатными кнопками экспорта соответствующего раздела. Сессии телефонов, коды сопряжения, cookies, учётные данные, диагностическая кампания, исходный кеш страниц, модели, пути контрольных точек обучения и активные задания исключены. Ранее выданные разрешения публикации сохранены как историческое свидетельство в квитанции, но не применяются как действующее разрешение на другом экземпляре; клиентские материалы надо пересоздать после проверки карточки.

Для каждого фото переносится последний паспорт выбора именно исходной группы этой карточки: полный список замеченных URL с происхождением, доступные и недоступные кандидаты, причина выбора и все сохранённые доступные исходники, включая отклонённые альтернативы и их подрезки. Исторические группы A/B с одинаковым основным URL сосуществуют; старая карточка без исходной группы не копирует и не наследует чужой последний паспорт. Недоступные URL не требуют скачивания при копировании. Перенос не содержит необработанную SQLite-базу решений: паспорт проверяется по SHA-256 группы и её связи с карточкой, реальным размерам/MIME/статистике байтов и правилам выбора, затем сохраняется в одной транзакции с карточкой и фото. Маленькое превью не получает статус полноценного исходника; приоритет ручной подрезки остаётся прежним. Другой выбор, уже сохранённый в принимающей базе для той же группы, не перезаписывается: нужен перенос в отдельную базу. Счётчик фото отражает исходный альбом, а не число разных размеров одного снимка; решения показаны отдельно в квитанции проверки.

## Проверка и перенос

Выполняйте из папки репозитория. Пути в примерах замените на собственные. Файл вывода и целевая папка должны ещё не существовать; рабочий кеш сервера не указывайте как место восстановления.

```bash
python3 cli/workspace_backup.py export --cache /path/to/source-cache --output /path/to/redcn-private-workspace.zip
python3 cli/workspace_backup.py inspect /path/to/redcn-private-workspace.zip
python3 cli/workspace_backup.py restore /path/to/redcn-private-workspace.zip --destination /path/to/new-workspace
```

Восстановление работает офлайн в отдельной новой папке. Сначала проверяются внешние и вложенные манифесты, SHA-256, размеры, пути, схемы досье и типы файлов. Затем внутри родительской папки собирается временная база. Только после успешной загрузки всех карточек, связанных данных и настроек выполняется атомарное переименование с запретом замены существующей папки (`renamex_np(RENAME_EXCL)` на macOS, `renameat2(RENAME_NOREPLACE)` на Linux). Ошибка второй карточки, неподходящая схема или появившаяся конкурентная папка не оставляют наполовину восстановленную рабочую базу и не заменяют чужие данные. Для нового сервера телефоны подключаются заново.

Ограничения: до 500 карточек, 512 МиБ ZIP, 1 ГиБ распакованных данных, 32 МиБ словарей/истории и 200 000 строк переносимых журналов. В браузере проверяется ZIP до 64 МиБ; большие файлы проверяются CLI. Недостающий оригинал фото или изменение карточки, заметок, фото, дизайна либо словаря во время сборки прерывают экспорт с требованием повторить его. Комплект не шифруется; это приватный архив с договорами и заметками, а не клиентский пакет.

## Что проверено, что требует внешнего решения

Изолированные тесты создают два синтетических досье, вымышленный договор, сгенерированные PNG, подрезку, две версии материала, общий дизайн, историю и учебную память. Проверены перенос в новую папку и повторный экспорт, ссылки между карточками, 19 источников фото при одном выбранном, оригиналы бренда без карточек, порча SHA/счётчиков/путей, конкурентное редактирование, сбой второй карточки, гонка появления целевой папки и границы токена/Origin/телефонных ролей. Тесты не читают файлы пользователя и не подтверждают перенос на второй физический Mac.

RCN-057 остаётся отдельным решением о настоящих пользователях/тенантах: действующие телефонные роли управляют общей рабочей базой. RCN-058 требует выбора провайдера, явной папки назначения и способа доступа. Автоматическая отправка в облако не включена; никакие приватные архивы тестами и этим обновлением наружу не отправлялись. Нельзя считать эти пункты завершёнными лишь по существованию локального ZIP.
