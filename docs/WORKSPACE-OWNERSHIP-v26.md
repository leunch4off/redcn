# RCN-057 · владелец рабочего пространства и доступ к объектам

Критерий: «Каждая серверная операция проверяет владельца объекта».

В этой установке владелец относится ко всему рабочему пространству Mac. Данные
карточек, фотографий, вложений, словарей, учебной памяти и истории находятся в
его отдельном `cache-dir`. Подключённые телефоны получают приглашение в это
пространство с явно назначенной ролью. Роль редактора не создаёт отдельную
частную библиотеку внутри общей базы.

## Исправленный способ входа владельца

Ранее любой локальный HTTP-клиент мог прочитать `/` и получить `redcn-token` из
HTML. Проверка заголовка на последующих запросах поэтому не обеспечивала
изоляцию владельца от другого локального клиента.

Теперь публичная страница, включая `/listing/<id>`, всегда содержит пустой
`redcn-token`. Карточки и список объектов в неё не встраиваются. Секрет владельца
создаётся в `desktop-owner.json` с правами `0600` внутри каталога `0700`;
символическая или жёсткая ссылка на такой файл отклоняется.

Первое открытие выполняет обычный локальный launcher. Он читает свою учётную
запись внутри программы, проверяет HMAC-подтверждение действующего сервера по
свежему случайному запросу и передаёт доступ браузеру в URL-фрагменте. Публичная
метаинформация `/health` сама по себе не считается доказательством владельца.
Программа не печатает секрет или URL с секретом. Фрагмент заменяется в текущей
истории до асинхронной инициализации и не попадает в HTTP URL или Referer.

Обмен принимает только JSON нужной формы и собственный Origin. Сервер выдаёт
производный `HttpOnly; SameSite=Strict` cookie на непредсказуемый частный путь.
Сам cookie не является API-токеном. Это существенно для localhost: cookies не
разделены по TCP-портам. Cookie с областью `/` не используется. Браузер хранит
только идентификатор частного пути, отдельно для origin и пространства; пароль
владельца не записывается в localStorage. API-токен получается через этот путь
при наличии соответствующего cookie и используется в оперативной памяти.

Обычная перезагрузка страницы и перезапуск того же сервера сохраняют вход.
Чистый браузер показывает законченный экран локального доступа, а не бесконечное
ожидание Mac. После первого обновления до v26 нужно один раз открыть редактор
через launcher:

```sh
cd ~/Downloads/redcn-v5
.venv/bin/python scripts/open-local-workspace.py
```

Для другого каталога или порта предусмотрены `--cache-dir` и `--port`.
Launcher не создаёт второй контроллер и не вызывает `recover_interrupted`.
Сессии телефонов не удаляются и не изменяются.

## Проверка области каждого запроса

`WorkspaceOwner` привязан к каноническому каталогу, его владельцу ОС и
идентификатору файловой системы. Перед обработкой desktop/phone запроса проверка
подтверждает эту область. Подмена корня или указание чужого хранилища для
контроллера отклоняется. Приватные хранилища не могут быть перенаправлены ссылкой.
Для фотографий отдельно проверяется адресованный файл и база медиа.

После этого действуют существующие проверки API-токена или сессии телефона,
Origin, CSRF и роли. ID карточки, вложения или изображения разрешается только
внутри базы этого пространства. Вложение дополнительно связано с карточкой;
экспорт связан со своей карточкой и политикой публикации. Полная резервная
копия доступна только desktop-владельцу. Восстановление является явным переносом
копии в новую библиотеку с новыми доступами, а не получением прав в исходной.

| Семейство операций | Область и полномочия |
| --- | --- |
| Карточки, история, задания, текст, импорт | Контроллер и его каталог; desktop credential либо приглашённый телефон с нужной ролью |
| Фото и превью | Та же база `media.sqlite3` и собственный адресованный файл; для viewer также связь с видимой карточкой |
| Вложения и готовые материалы | База `card-assets`, связь с текущей карточкой, роли и политика клиентского экспорта |
| Словарь, обучение, дизайн, маршруты, уведомления | Метаданные данного каталога; роль проверяется до dispatch |
| Приватный перенос всей библиотеки | Только локальный владелец; credential и сессии не экспортируются |
| `/health`, план, публичная оболочка | Только агрегаты или общие данные, без объектов и секретов владельца |

Cloud Worker не хранит частные карточки на сервере: он возвращает общие
справочники и результаты отдельного разрешённого запроса. Частная облачная
публикация сохраняет прежнюю аудиторию Sites; пользовательские локальные базы
не превращаются в общую серверную таблицу.

## Воспроизводимые проверки

`tests/test_workspace_ownership.py`: два независимых рабочих пространства и
настоящие HTTP-серверы, различные токены, попытки подменить владельца, чужие ID
карточек/файлов, коллизия одинакового ID с разным содержимым, изолированный ZIP,
чужая сессия телефона, подмена SQLite ссылкой, права credential, HMAC-проверка
launcher и сохранение cookie после перезапуска. 13 проверок прошли локально.

`tests/desktop-owner.test.mjs`: удаление фрагмента до обмена, отсутствие запросов
из публичной/закрытой страницы, ограниченный обмен, восстановление по частному
пути, отсутствие credential в browser storage и закрытый доступ при отказе.
Шесть проверок прошли локально. Secret scanner также запрещает случайно
добавленный `desktop-owner.json`.

`tests/test_workspace_ownership_browser.py`: три дополнительных сценария
настоящего Chrome — анонимный экран, вход/перезагрузка и перезапуск сервера.
Локальный Linux-прогон пропустил этот класс из-за отсутствия Chrome/Playwright;
результат обязательной проверки с установленным браузером добавляется в общий
журнал выпуска. Эти сценарии не выдаются за выполненную физическую проверку
другого Mac или другого системного аккаунта.

Проверка относится к полномочиям серверных запросов и изоляции штатных рабочих
пространств. Администратор ОС и код, исполняемый от имени владельца его файлов,
находятся внутри доверенной границы этой локальной установки.
